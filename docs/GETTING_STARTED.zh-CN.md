# 上手指南

[English](GETTING_STARTED.md) · [仓库首页](../README.zh-CN.md)

以下命令均在 PersonaStudio 仓库根目录执行。启动器通过 uv 使用应用锁文件，并以普通安装方式运行 Python 包，无需手动激活虚拟环境，也避免同步文件夹中可编辑安装入口失效的问题。

## 1. 准备环境

使用 macOS 或 Linux，并先[安装 uv](https://docs.astral.sh/uv/getting-started/installation/)。应用要求 Python 3.12 或更新版本，Python 环境由 uv 管理。当前进程管理和文件锁依赖 POSIX API，暂不支持原生 Windows；WSL 可以作为 Linux 环境尝试，但需要在实际机器上验证浏览器访问、文件权限和应用接入。

启用 AI 模型功能时才需要 Node.js 22.19 或更新版本，并包含 npm。只浏览和手动编辑人格无需 Node.js 或模型账号。

## 2. 选择工作区

```sh
./scripts/ai-persona setup
```

本地浏览器向导提供体验 Demo、新建空白工作区和打开现有工作区。请选择仓库之外的绝对路径，例如个人主目录中的 `PersonaWorkspaces` 文件夹。新建操作不会覆盖非空目录。「打开现有工作区」直接使用原目录；如果需要独立副本，请使用[迁移功能](DATA_MANAGEMENT.md)。

向导默认继续打开「模型设置」，依次引导环境准备、账号接入、认证和连接测试。也可以取消“打开后引导我设置 AI”，先浏览和编辑。向导不会安装 Codex Hook 或开启对话学习。

也可以直接启动 Demo：

```sh
./scripts/ai-persona start --demo
```

Demo 首选 8766 端口，被占用时自动选择空闲端口，浏览器会打开实际地址，无需停止已有 Studio 或远端网关。内置的虚构科研人格包含知识、阅读材料、偏好与正反样例。操作保存在独立副本中，不改写随包模板；模型连接及自动接入与真实人格隔离。

## 3. 体验日常流程

1. 打开「知识」，从图谱进入一个知识点。
2. 打开「材料」，阅读示例原文并查看关联知识。
3. 打开「偏好」，修改一条规则或样例。人工保存后立即生效，并保留历史。
4. 配置 AI 后，请「AI 维护助手」提出修改，再到「反馈与审核」检查、编辑、通过、拒绝或暂缓候选。

「评测与改进」包含测试样例、运行评测、评测报告与改进参考。明确点击反馈才形成个人测试样例；审核候选与评价反馈是两个独立操作。

## 4. 按需启用 AI

打开「设置 → 模型」，按页面上的四步提示操作：

1. **准备环境**：页面检查 Node.js 和模型组件。缺少 Node.js 时提供官方下载入口；安装 Node.js LTS 后重新检查，必要时重启 Studio。组件未安装时直接点击「安装模型组件」，不用另开终端。下载失败可以重试，安装期间刷新页面可继续查看进度。
2. **添加账号**：选择平台、连接名称与认证方式。原有的 API Key 和支持的平台账号授权均保留。
3. **认证**：API Key 由你在本机表单填写；账号授权请打开提供方链接，完成登录或按页面提示输入授权结果。未完成的授权可恢复或取消。保存凭据只表示本机已保存，不代表模型访问已经验证。
4. **测试并保存**：选择默认账号与模型，主动点击「测试连接（真实调用）」，成功后保存模型设置。测试发送一条简短请求，不发送工作区材料，但可能消耗账号额度。页面仅在对应连接版本与默认模型测试成功后显示「AI 连接已验证」。修改连接后需要重新测试。

只浏览和手动编辑不需要完成这些步骤；随时可以选择「先浏览，稍后设置」。认证范围与验收边界见[模型接入与认证](MODEL_CONNECTIONS.md)。

命令行安装仍然可用，遇到持续失败时也可用于查看详细原因：

```sh
./scripts/ai-persona models-install
```

模型组件保存在 Python 包之外的应用缓存目录；账号独立加密存储，安装或重试不会删除账号。Demo 与真实工作区的凭据隔离。安装按钮只允许在运行 Studio 的电脑上使用；通过远程入口访问时，请先在服务所在电脑准备环境。

对话学习与偏好应用是可选且独立的功能。请先配置来源与范围，再按需启用，详见[集成说明](INTEGRATIONS.md)。

## 5. 启动、诊断与停止

通过向导选择真实工作区后：

```sh
./scripts/ai-persona start
./scripts/ai-persona status
./scripts/ai-persona doctor
./scripts/ai-persona stop
```

针对 Demo 的工作区命令加上 `--demo`：

```sh
./scripts/ai-persona doctor --demo
./scripts/ai-persona stop --demo
```

未指定 `--port` 时，`setup` 和 `start` 首选真实工作区的 8765 或 Demo 的 8766 端口，被占用时自动选择空闲端口。同一工作区已有健康服务时会复用。无需为了打开工作区而停止其他 Studio 或远端网关；请使用浏览器打开的实际地址，或通过 `status` 查看。

显式指定 `--port` 表示必须使用该端口，冲突时仍会报错。前台 `serve` 保持固定端口行为，不会自动换端口。`stop` 停止 Studio；维护后台学习或模型服务时，需要分别停止对应组件。

```sh
./scripts/ai-persona logs
./scripts/ai-persona models-stop
```

旧的全局 `ai-persona` 与本仓库属于不同安装，迁移期间请统一使用仓库启动器。旧 Studio 运行期间可以直接体验独立 Demo；若要让同一个已有工作区加载本仓库的新代码，请等任务完成后，再通过新启动器重启该工作区的服务。
