# Ideas：私人研究笔记

Ideas 已接入 Studio 导航，沿用原有侧栏、蓝色按钮、卡片、表单和中英文切换。入口为 `/ideas`。真实工作区首次进入为空；新版 Demo 模板有五个虚构示例，覆盖全部执行状态和结束结果。已有 Demo 副本不会被覆盖。

## 使用

- 新建只需标题。正文支持常用 Markdown 安全预览，图片作为引用链接，不自动下载。
- 新颖性、实现难度分别有独立的可选说明。尚未判断时也能写说明，切换选项不会清空说明。
- 执行状态为未开始执行、执行中、已结束。结束必须选择成功完成、部分完成或放弃，并填写非空说明；确认会一并保存当前修改。取消保留未提交草稿。
- 重新开始会清空当前结束结果、切换为执行中，保存后生效。上一轮结果保留在历史中；再次结束需要重新选择和填写。
- 归档独立于执行状态，可恢复。
- 资源支持 HTTP(S) 链接、文件上传和引用已有 Source 文件，可编辑名称、备注与顺序。移除引用不删除文件，包括历史版本引用的文件。
- 列表按更新时间倒序；搜索正文、判断说明、结束说明及资源信息。筛选同组多选为 OR、不同组为 AND，不暗中调整其他筛选。
- 显式保存，支持 Ctrl / Cmd + S。无变化不产生版本。草稿保存在工作区，包含未提交的结束说明；刷新后可恢复。并发冲突保留输入，并提供最新记录的查看入口。
- AI 上下文只预览、复制当前已保存内容，可选资源元信息；不读取附件、不访问链接、不请求模型。

## 存储和边界

正式记录在 `persona-data/records/ideas/idea_*.md`，schema 为 `ai-persona.idea/v1`，属性放在 YAML frontmatter，正文为 Markdown。

完整历史在 `persona-data/revisions/ideas/<idea_id>/<revision>.md`。保存沿用 Persona 写锁及内容清理互斥机制，先持久化完整快照，再原子替换正式记录。正式记录的 revision 是提交点；高于它的未提交快照不进入历史，下一次保存可覆盖中断留下的未提交快照。已提交历史不改写。

Ideas 使用自己的 revision，不推动公开 Persona revision。公开快照、知识索引、新旧 MCP 查询、AI 维护目录及自动上下文均不提供 Idea 内容。新附件使用 Source manifest 的 `idea_attachment` 类型，移除引用后仍禁止自动查询读取。非 Idea 记录不能把私人附件或 Idea 用作来源、图谱端点或证据。引用原本共享给 Persona 的 Source，不改变该 Source 既有的可见性。

附件下载按 manifest 声明路径解析并校验哈希，返回 attachment、二进制内容类型和 nosniff，不内联执行。私人附件缺失或变化只影响下载，不阻塞笔记编辑。完整工作区备份包含记录、历史、Source 和草稿；重建索引不清除草稿。清理预览包含 Ideas，清理后旧版本不能继续提交。

## 上传限制

默认单文件 20 MB，可在工作区 `persona-data/config/persona.toml` 配置为 1–50 MB；页面提前显示限制，服务端同步执行：

```toml
[ideas]
max_upload_mb = 20
```

## 验证

后端：`apps/ai-persona/tests/test_ideas.py`。覆盖结束、重开、判断说明、无操作保存、并发、写入失败、中断恢复、资源路径、缺失文件、查询边界、备份草稿恢复和清理预览。

浏览器：仓库根目录运行 `npm run test:ideas`。使用隔离临时工作区，覆盖真实保存、三种结束、草稿恢复、重新开始、资源与历史、上下文、失败与冲突、Markdown 安全、中英文和移动端。截图在忽略目录 `.qa/ideas-production/`。

旧独立演示保留于 `docs/prototypes/ideas/`，浏览器数据不会自动导入正式工作区，也不会自动映射旧失败或暂停状态。
