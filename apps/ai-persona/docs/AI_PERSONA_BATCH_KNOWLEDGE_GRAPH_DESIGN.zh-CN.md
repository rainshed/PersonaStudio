## 1. 目标与阶段边界

用户一次输入多个 arXiv 链接，或混合上传多个 Markdown、PDF 等第一阶段已支持的文件，共用一份整理目标和提取规则。系统分别读取材料、保存带证据的候选，再进行跨材料查重和整合，形成一套可预览、可审核的知识图。

```text
批量添加材料 → 确认集合目标与规则 → 各材料独立读取与提取
            → 跨材料整合 → 知识图与变更预览 → proposal 分组审核
```

这一阶段不要求新增其他 Agent、OCR、任意网页解析或后台论文监控，也不改变用户审核后才修改正式知识库的边界。知识图范围是本次材料集合及其关联的已有知识，不宣称生成某一领域的完整知识图。

单材料任务可视为集合大小为一的情况。复用第一阶段的来源、规则、证据、读取和提交服务；第一阶段只需保留可扩展的接口，不提前实现批量调度和全局合并。

## 2. 输入与集合目标

- 支持多行粘贴 arXiv ID/链接，以及一次选择多个文件。
- 可以混合链接和文件；格式与解析能力沿用第一阶段。
- 导入后展示材料清单、解析状态、重复提示和固定版本；用户可在开始前移除材料。
- 整个集合共用任务目标、知识点定义、关系规则、关注领域和阅读模式；保留每份材料的来源身份与覆盖范围。
- 不要求逐篇重复填写规则，不因批量分析推断阅读状态、掌握程度或兴趣。

同一 arXiv 版本的 PDF、Markdown 等表示应检查是否对应同一材料，不能直接当成两份独立支持证据。基础 ID 相同而版本不同的材料保留版本关系，不把新旧版本的结论无条件混合。

集合成员和目标均有版本。开始后新增或移除材料产生新的集合修订，不无声改变正在运行的分析范围。

## 3. 分别提取与统一整合

### 3.1 各材料独立处理

每份材料使用第一阶段的按需读取、章节覆盖、查重、候选和证据工具，独立保存检查点。初始上下文不同时展开全部材料正文。

候选使用包含来源任务身份的稳定临时引用，避免不同论文的同名临时编号冲突。跨材料整合读取精简候选及证据引用，必要时回到对应原文补读；不把全部原文和所有执行历史再次一次性送入模型。

### 3.2 跨材料合并规则

| 情况 | 处理方式 |
|---|---|
| 多篇材料讨论同一概念 | 归并到已有节点或同一个新增候选，分别保留材料关联与依据 |
| 缩写、译名、别名不同 | 查询定义与上下文后判断语义同一性，不仅依靠字符串相似度 |
| 名称相同而含义不同 | 保持独立，补充适用范围或消歧说明 |
| 已有同一条关系 | 优先补充依据和必要的限定说明，避免重复连线 |
| 同一关系在不同条件下成立 | 保留各自条件，不因合并丢失研究对象、参数或适用范围 |
| 不同材料结论冲突 | 并列记录各方论断和依据，进入待核对项，不通过多数投票覆盖 |
| 仅在多篇材料中共同出现 | 不据此自动建立关系 |
| 没有新增知识点 | 可以只增加材料、材料关联或依据；必要时登记 no_change |

知识点继续遵循第一阶段“有明确名称、可独立检索、可跨材料复用”的定义。材料增加不应导致节点数量机械增长；不设置每篇必须产出多少节点的配额。

### 3.3 综合判断的边界

明确区分“材料直接支持的陈述”和“跨材料综合判断”。后者必须列出参与综合的来源、简短理由、条件及不确定性，不能伪装成任一论文的直接陈述。

在现有证据契约尚不能准确表达这种区分时，综合判断只保存在待核对的候选说明中，不直接编译成有原文支持的正式关系。对证据类型的扩展需要版本化契约及相应审核展示。

## 4. 知识图预览与 Proposal

结果提供两个互相对应的视图：

- **知识图预览**：展示本集合涉及的已有节点、新增候选、拟修改关系，以及材料与知识的联系。
- **变更清单**：展示动作、理由、来源证据、条件、冲突和延后项，可直接定位原文。

点击知识节点可看到哪些材料讨论它；点击关系可看到具体陈述及对应证据。用标识和文字区分已有、待新增、待修改、待核对内容，不只依靠颜色。

预览由已保存、已校验的候选和正式记录生成，与待审核 proposal 一致，不让模型额外生成一份脱离提案的图。拒绝、编辑或采纳后，预览同步反映实际状态。

提交复用第一阶段的幂等和校验机制，形成关联的 proposal 组。分组遵循依赖关系：不能采纳一条引用尚未成立节点的关系。允许用户按组审核；不因为点击“生成知识图”而自动采纳所有修改。

## 5. 进度、失败与增量更新

- 集合有总体状态，每份材料有独立的解析、运行、失败和完成状态。
- 一篇失败不使其他材料的有效结果失效；可单独重试失败材料。
- 页面同时显示“材料处理进度”和“跨材料整合进度”，不能把全部材料提取结束等同于知识图已经完成。
- 允许用户先整理和审核成功部分，但必须明确列出本次结果包含的材料、失败材料、未处理章节和延后项。
- 部分结果提交后，剩余材料完成时生成新的集合结果修订；重新查询已采纳记录，避免重复创建节点和关系。
- 后续向同一集合补充材料时，复用仍有效的来源分析，重新核对新增材料影响的概念、关系及证据；不直接改写旧 proposal。
- 移除集合中的材料不自动删除知识库已有事实。若需要撤回依据或关系，应生成独立、可审核的维护建议。

恢复和取消沿用第一阶段的任务版本、run_id 和写入资格校验。调度设置并发、总调用和用量预算；首版可以顺序执行，批量能力不以并发或多子代理为前提。具体默认上限在实现时根据 Codex 限流和真实样本验证确定。

## 6. 数据与接口扩展

在第一阶段之上增加以下概念，不另建一套知识库：

| 概念 | 保存内容 |
|---|---|
| 材料集合任务 | 集合 ID、修订、目标与规则快照、成员列表、工作区版本 |
| 单材料子任务 | 关联第一阶段任务 ID、来源版本、状态、覆盖和检查点 |
| 整合检查点 | 已处理候选、临时引用到统一节点的映射、冲突、补读需求 |
| 结果修订 | 本次纳入的成员和候选版本、未完成范围、对应 proposal 组 |

Agent 的每次输入块仍带来源。材料证据分别绑定 source_id、版本、表示和位置；整合结论额外列出多个来源引用。工具范围由集合成员和明确允许的现有记录决定，不能因批量模式扩大到其他工作区。

通用后端接口继续负责启动、继续、取消和事件转换。批次调度、语义映射的持久化、提交依赖和审核状态由 AI Persona 管理，避免耦合于 Codex 的子代理实现。

## 7. 第二阶段验收

| 场景 | 验收要求 |
|---|---|
| 批量输入 | 多链接、多文件和混合输入均可逐项反馈；重复与版本差异清楚可见 |
| 统一目标 | 集合规则只需设置一次；每份材料使用可追溯的目标快照 |
| 概念归并 | 同义概念合并、同名异义区分、已有节点复用，语义歧义进入待确认 |
| 多来源证据 | 合并后来源、版本和条件不丢失；同文不同表示不冒充独立证据 |
| 关系质量 | 不因共现连线；保留冲突与限定条件；综合判断不伪装为直接证据 |
| 图与提案一致 | 图上每项待变更均能对应候选/提案，审核后正确更新 |
| 部分失败 | 单篇失败可单独重试；部分提交明确范围，继续后不重复建点或提案 |
| 增量材料 | 新增成员仅复用有效结果，重新验证受影响关系；移除成员不自动删库 |
| 依赖与恢复 | 分组审核无悬空引用；取消和迟到响应不能覆盖有效结果 |
| 输入与调度预算 | 不一次性展开整批原文；并发和总预算可控；来源数量增加时不会无限启动任务 |

评估既检查单篇提取质量，也检查跨材料合并的误合并、漏合并、重复关系、证据丢失和条件丢失。对确定性去重、引用映射及提交验证输入顺序不变性；模型语义结果不要求逐字一致，但不能仅因导入顺序不同而覆盖冲突或造成悬空引用。

## 8. 实施顺序

1. 集合输入、成员去重/版本管理与单材料任务调度。
2. 跨材料候选归并、来源证据合并、冲突和条件保留。
3. 知识图预览、变更清单与 proposal 依赖分组。
4. 单篇重试、部分提交、增量材料与预算控制。
5. 混合材料端到端验收和用户说明。

第一阶段以单材料闭环为交付目标；第二阶段以材料集合的统一知识图为交付目标。本文件保留两阶段规划与验收目标；实际交付边界、预算和验证结果以实现说明为准。
