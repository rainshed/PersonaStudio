# 偏好自动应用使用说明

日期：2026-09-08。首版适配本机 Codex。产品规则和契约见[设计文档](AI_PERSONA_PREFERENCE_ACTIVATION_DESIGN.zh-CN.md)。

## 查看与设置

在「我的偏好」点击「应用记录」，或打开 [偏好应用记录](http://127.0.0.1:8765/preferences/applications)。

展开「自动应用偏好」，可以选择 Codex 来源、独立开关和每轮等待上限。来源及项目范围复用「设置 → 应用接入」中的 Codex 配置；偏好应用不依赖学习功能是否开启。新安装默认关闭。本机此次交付已为现有「codex全局」来源开启，等待上限为 5 秒。

页面保存设置后，后续请求使用新值，不必因为调整等待时间重新安装 Hook。设置为较大值时，模型服务自身的任务上限仍可能先到达。

## 完成 Codex 首次接入

本机已把旧版学习和偏好两个处理器替换成一条统一处理器，配置位于用户级 `~/.codex/hooks.json`，修改前在同目录备份。对话学习页和偏好应用页生成的是同一份配置，同一来源只需安装一次。

Codex 对新增或变更的 Hook 要求单独审核和信任。进入 Codex CLI 的交互界面，输入 `/hooks`，审核并信任状态文案为「正在处理 AI Persona」的条目。这个步骤属于 Codex 宿主信任，页面中的「已开启」只表示 AI Persona 应用开关，并不代替该审核。[Codex 官方说明](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)

Codex 已识别唯一的统一入口，配置没有错误，当前信任状态为「已修改」；命令改变后需要重新审核信任。完成信任前，对话学习和偏好应用都不能通过新入口自动触发。完成后，在实际使用的 Codex 中提交一条新的用户请求，再到本页点击「刷新记录」。如果当前客户端没有重新加载 Hook，按该客户端方式重新进入任务或启动会话。

其他安装位置可先在「模型设置」配置偏好场景判定模型，再通过「设置 → 应用接入」的 Codex 引导创建来源、安装统一 Hook 并发送测试消息。也可手动把生成的 `UserPromptSubmit` 处理器合并进 Codex Hook 配置；若同一来源已有旧版学习或偏好处理器，用统一条目替换它们，保留其他事件与处理器。不要重复安装，也不要用复制的片段覆盖整个配置。也可在工作区运行：

```bash
ai-persona preferences-apply hook-config --connection '<来源 ID>'
ai-persona preferences-apply status
```

同一个来源只安装一次。运行所需的路径会包含在生成配置中；工作区、解释器或安装位置改变后需要重新生成并审核。

## 每轮会发生什么

1. Codex 将当前请求送到统一处理器，AI Persona 校验来源与开关，一次提取正文并固定必要背景。若学习已开启，同一份输入通过独立进程持久入队，由现有 Worker 后台处理。
2. 模型对每个有效场景给出命中或不命中，允许多个命中。没有第三种语义结果。
3. 程序收集命中场景的所有正式偏好、参考样本及全局偏好，按记录 ID 去重，生成一份 JSON。
4. 统一处理器只把准备好的偏好作为当前轮上下文返回给 Codex，学习结果和入队回执不混入。超时、模型失败、输出不合法或组装失败时正常退出，不返回任何本轮偏好，包括全局偏好。

学习入队与偏好判断分别处理失败，互不作为成功前提。入队进程最多运行 3 秒，当前轮不等待其完成；模型分析仍由后台 Worker 按学习设置处理。

全部场景不命中仍属于判断完成，可以提供全局偏好。没有可提供内容时正常无输出。重复交付同一事件不会重复调用或注入；下一轮重新判断。此前已经进入对话历史的旧内容不会因本轮失败而被撤回。

提供的内容包含统一来源说明：这些是用户保存或确认的长期偏好，供当前任务参考，本次明确要求优先。偏好原文、条件、理由和强度保留；场景判断理由、运行日志和反馈数据不混入偏好正文。

文件夹样本提供名称、文件数量和实际路径，资源不可访问时标明不可用。此版本不自动阅读样本全文，也不新增文件夹内容检索流程。

## 阅读记录和提交反馈

左侧选择一次请求，右侧依次查看状态、命中场景下的偏好、全局偏好和参考样本。可以打开样本、查看文件夹或复制路径；展开原始 JSON 可核对实际准备的内容。

| 状态 | 含义 |
| --- | --- |
| 正在判断 | 当前处理尚未结束 |
| 上下文已准备 | 内容已经组装，尚未确认处理器完成输出 |
| 已返回 Codex | 处理器已经输出完整内容，不代表 Agent 已实际遵循 |
| 没有需要提供的偏好 | 判断完成，但没有相关偏好或样本 |
| 本轮未提供偏好 | 查看失败原因；不应自动理解为场景不命中 |
| 本轮已跳过 | 例如只有宿主附带状态、没有用户正文 |

在场景判断区域，可对命中和未命中的场景分别点击「满意／不满意」，也可撤回。对未命中的场景点「不满意」表示漏触发；对命中的场景点「不满意」表示误触发。只有明确评价才形成样例，不自动反转其他场景。

判断未完成的记录不生成场景正确性标签。若判断已完成、但内容在组装或返回前失败，仍可评价当时的有效判断。反馈和冻结输入复用「反馈与测试样例」及回放功能，不会自动更改正式偏好、场景或线上提示词。

## 运行边界与定位

- **没有任何应用记录**：先确认独立开关、所选来源、原来源范围，以及 Codex 是否已加载并信任新 Hook。
- **记录为未提供**：查看具体原因。未配置场景判断模型、非法输出、超时和内容变化是不同失败，不应通过提供全局偏好掩盖。
- **超过本轮等待上限**：预算包含输入准备、模型判断与内容组装。模型开始返回内容不等于判断已经完整完成；到期仍没有完整结果就不提供偏好。可结合实际延迟调整等待上限，调整不会追补失败轮次的内容。
- **旧记录显示模型服务未能及时响应**：早期版本把本地 HTTP 响应超时也记为 `runtime_unavailable`。已修正为独立的 `timeout`，后续记录会显示「超过本轮等待上限」；原有历史记录保留，可对照模型运行日志判断原因。
- **完整内容超预算**：默认上限为 24,000 个 UTF-8 字节，不静默裁切偏好或返回半段 JSON；技术配置可通过本机 API 或 `configure` 调整。
- **样本不可用**：其他偏好仍可以完整提供。页面保留资源信息，供定位路径；不会声称已经读取样本。

运行记录与独立设置保存在 `persona-state/preference-applications.sqlite3`。用户反馈仍按现有评价系统保存和备份。界面目前提供逐次记录与耗时，尚未新增总体完成率和延迟分布看板。

## 本次验证范围

统一 Hook 改造后 Python 全套 452 项通过，其中统一入口新增 14 项，覆盖共享采集、开关组合、失败隔离、入队锁等待及实际进程和模型桥接。正式页面已验证共用接入说明；两页生成的配置与本机安装文件完全一致。此前还完成了场景阅读、文件夹路径、反馈与撤回验证；模型运行时 39 项、页面脚本 42 项通过。合并前真实模型隔离测试的两次耗时为 3.22 秒与 2.36 秒，分别覆盖命中并返回、无命中且无内容。

上述测试不等同于真实 Codex 对话已经收到上下文。首次信任完成后，仍需验证新增事件产生应用记录，并确认内容在当前轮首个模型请求前可见。
