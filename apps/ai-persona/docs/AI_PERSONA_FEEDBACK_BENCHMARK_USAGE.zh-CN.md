# 反馈与个人测试样例使用说明

更新日期：2026-09-09。触发反馈接入对话学习和偏好场景判定；材料整理、自然语言维护及独立 AI／MCP 候选在同一工作台审核，但不收集触发反馈。

## 日常使用

日常操作进入「反馈与审核」（`/inbox`）。已有测试样例、隔离回测和报告进入「评测与改进」（`/evaluations`）；Prompt Workbench 选择 AI Persona 后复用同一评测数据集合，不是第二套反馈库。

1. 在「反馈与审核」选择记录，详情中直接评价本次学习是否应该触发；进入审核、不进入审核都可评价，列表持续显示反馈与审核进度。偏好场景逐个评价，未命中场景可展开并搜索。从「偏好 → 试判场景」主动调用模型后也回到同一详情反馈；MCP 场景判定响应提供 `result_id` 和本机反馈路径。
2. 只需点击「满意」或「不满意」，点击成功即保存必要输入和标签。不点击不会成为测试样例，不用另点加入。
3. 不满意后可选填写理由，按「保存理由」。理由仅供修改提示词；查看入口为「评测与改进 → 开始检查 → 手动改进 → 查看所选样例的改进参考」。理由不进入触发模型载荷或评分；自动改进时，仅开发样例的理由会发送给改进模型，理由修订纳入该任务的预览校验。
4. 对话学习生成的内容继续走正常审核。直接通过或修改后通过，会自动把当时确认的业务内容保存为参考答案；先审核后反馈也能关联。拒绝、暂缓、未审核不会自动变成内容答案。
5. 误点可在原处「取消反馈」；当前选项再次点击不会重复保存，改选会更新同一条样例。取消不删除学习任务、候选或 Persona，也不是永久擦除历史快照。需要彻底删除时使用样例管理页的明确删除入口。

触发反馈评价的是**判断**，不是生成内容。满意沿用原布尔结果，不满意将原结果取反。偏好场景按场景分别计分，没有评价的场景不计分。超时、失败、等待上下文不是「不触发」，没有确定判断时不显示反馈按钮。因去重没有新提案也不代表学习未触发。

新版本开始记录新运行的结果，不自动把历史任务、旧工作台样例、已有审核内容转换成个人测试样例。启动中的旧 MCP 进程需由宿主重新连接后才加载新代码；Hook 配置无需修改。

## 开始检查

页面有「开始检查」「测试样例」「历史记录」三个入口。检查内容只有「对话学习触发」和「偏好触发」。第一次进入默认选择最多 200 条有效样例，仍可在测试样例中逐条选择；没有样例时指向原反馈入口。

1. 选择「检查当前方案」「手动改进」或「自动改进」。选择已有测试集可复用当时冻结的样例修订，已撤回标签仍被排除。
2. 选择每条样例、每个方案重复 1、3、5 或 10 次，默认 5 次。例如 10 条样例、两个方案、重复 5 次，共 100 次独立检查。重复运行会实际调用模型，不复用上次输出。
3. 比较时，A 是当前方案，B 从当前方案复制。可分别勾选修改提示词、更换模型、调整思考强度。提示词可直接编辑、另存为版本并选入 B，不会立即启用。未勾选的项目沿用当前配置。
4. 确认页展示 A/B 各自的连接、模型、思考档位和提示词版本，并展示预计运行量与限额。勾选发送必要输入后点击「开始检查」才调用模型。如果预览之后配置或样例变化，开始请求会被拒绝，需更新预览。

A 显示当前方案真实保存的思考强度；未指定时显示「跟随模型默认（未指定）」。B 仅展示模型目录支持的档位；不支持配置的模型保持默认。档位会传到 Pi 的实际生成请求，并随输出记录。自定义模型没有声明档位时不冒充支持。不提供不生效的「关闭思考」选项。

对话学习触发使用冻结的对话输入和必要上下文；若模型需要更多上下文，只能补充样例中已经保存的上下文。偏好触发使用冻结的输入及原完整场景目录，只对已明确评价的场景计分。处理步骤固定，页面解释当前流程，不提供不存在的流程版本选择器。旧的候选生成、完整流程 API 与历史报告继续保留。

检查开始时固定样例修订、提示词内容与依赖、每个方案的模型连接修订及参数、流程代码摘要。A/B 按样例和轮次交错运行，交替先后顺序；不重试、不切备用模型。手动模式的反馈理由只出现在供人参考的折叠区；自动模式会将开发样例的理由发送给改进模型。触发模型始终看不到标签、理由或改进分析，评分由程序对照明确标签完成。

页面默认最多 100 次调用、保守预留 200,000 token、900 秒，可以在「运行限额」调整。调用限额小于预计用量时会提示可能只能完成部分检查。token 预留按 UTF-8 输入字节和输出上限估算，不是计费值；实际用量另行保存。每个 Studio 同时只执行一个检查或自动改进任务。

达到预算、停止或服务中断都会保留已完成结果，并标出未完成项目。刷新页面只恢复配置及查看记录，不自动重发。重复提交使用请求标识避免同一开始请求创建两次检查。服务重启后，未完成检查标记为中断。

## 自动改进

1. 独立选择「改进模型」和「触发模型」，分别设置目录支持的思考强度。改进模型负责分析错误、提出提示词；触发模型负责实际运行候选，整个任务中保持固定。A 保留当前提示词、模型及参数。
2. 可以从当前提示词开始，或选择已保存的手动草稿作为起点。手动和自动配置在切换时分别保留。
3. 预览页展示开发／验收样例数量、最多轮数和总额度。默认最多 3 轮，每轮一个候选；连续两轮没有可接受的改进就停止。原则是简洁、通用，优先澄清共同边界和合并重复内容。
4. 按已保存的会话、任务和相同输入分组，避免同源样例跨区。开发和验收都需覆盖两类判断；以前检查或自动改进已使用的样例不再充当未见验收。样例不足则仅作探索，页面明确标注缺少独立验收。来源缺失、语义相近的样例仍需要人工判断独立性。
5. 先检查起点，再以所选触发模型交错比较上轮保留方案和新候选。两类正确率都不下降、至少一类提高时保留；同样正确时优先更短的版本。未完成判断不允许通过缩小分母成为赢家。任一类别退步时保留原候选。
6. 程序优先预留验收调用和 token 额度；不足以完整比较新候选时停止搜索。最终候选固定后，仅验收一次，不将验收错误送回改进模型继续调整。再次改进使用新的任务，旧验收样例视为已暴露。
7. 完整报告列出每轮修改说明、模型推测、真实分数、实际提示词差异和模型变更，分别记录改进模型、当前方案触发模型、候选方案触发模型的调用与用量。点击阶段可查看逐次输出。实际计费若由供应商返回，保存在调用记录的 usage 中，不根据 token 预留自行估价。

提示词与触发模型一起启用，改进模型不进入生产。该能力的覆盖配置与提示词版本保存在同一 SQLite 事务中，生产请求从同一快照读取两者；全局账号凭证不复制。模型设置页展示实际生效的覆盖配置。用户明确重新保存模型设置后，以新保存的设置为准；思考强度需要更新后的模型服务支持。更改连接凭证或模型定义后，旧方案可能需要重新检查，系统不会悄悄替换模型。

自动生成的未启用草稿随评测任务保存，不会自动进入正式提示词库。用户明确接续手动编辑或启用后才另存为配置版本。删除源样例会清理整个相关自动改进任务及子报告中的派生正文，迟到写入不能恢复它；已经由用户明确另存或启用的配置版本属于提示词管理，不会因为删除评测报告而改动当前生产配置。

## 看报告和继续改进

报告描述的是「个人已评价样例表现」，不代表全部生产流量。每个方案分开显示：

- **不该触发的正确率：** 期望不触发且实际不触发的数量 / 获得明确判断的期望不触发数量。
- **该触发的正确率：** 期望触发且实际触发的数量 / 获得明确判断的期望触发数量。
- **重复判断一致率：** 同一案例、同一评价对象在所有重复中判断一致的数量 / 所有重复都得到明确判断的评价对象数量。只运行一次不计算一致率；一致也可能一直判错。
- **失败、未判定、未运行完成、等待中：** 分别列出，均不冒充不触发。没有对应类别样例或没有已完成判断时不显示 0% 或 100%，而显示无法计算及原因。

正确率同时展示正确数与有效判断数。偏好场景逐个计分，未评价场景不会混入分母。结果按样例展开，可逐次对照 A/B 的期望、实际、状态，以及每次输出和调用记录；每条记录有独立 ID 和 `repeat_index`，不会互相覆盖。可以筛选有错误或未完成的结果、重复不一致的结果。页面不自动宣布胜负，也不把成本、速度和正确率加成一个综合分数。

点击「用这些样例手动改进」保留同一测试集和样例修订，将上次候选恢复为编辑起点，A 重新取当前方案。候选保存和测试都不会修改真实 Persona、创建真实待审核提案或启用提示词；报告中的「启用候选方案」才会同时应用该能力的提示词、触发模型和思考强度；可用「回退整套方案」恢复上一套配置。当前方案或连接已变化时，会要求重新比较。

旧报告仍提供原生成内容、审核参考和本次模拟输出。内容语义评价由人工对照，不进行逐字匹配，也不调用额外裁判模型；评价关联具体样例、方案和重复轮次。通过部分候选时，参考答案只代表已通过部分，后续普通 Persona 编辑不回写过去的答案。

## 保存、撤回和迁移

持久用户数据保存在 `data_root/evaluations/`，通常即 `persona-data/evaluations/`：

```text
cases/         样例及不可变 benchmark 修订
feedback/      满意度、可选理由及反馈修订历史
blobs/         内容寻址的运行输入、环境与结果快照
suites/        固定测试集，每次创建新 ID
runs/          回测版本、用量、输出、报告与内容评价
deleted/       删除标记（阻止迟到任务复活原样例）
.transactions/ 可恢复的多文件提交日志
```

它不进入 `records/`、Persona revision、日常检索、编译快照或 Agent 的日常上下文。未评价运行只在 `state_root/evaluations/traces/` 临时保留，默认 7 天／100 MB；访问反馈接口时按小时触发清理检查。一天以内的运行中记录受保护，已失去工作进程的旧记录不会无限保留。已评价样例的附件独立持久保存，不依赖临时任务或 captures。

- **撤回反馈：** 可撤回整个样例或某个已评价场景，取消正在使用它的回测。旧测试集也不能绕过撤回。可以重新明确评价。
- **删除样例：** 二次确认后清除本地样例、理由、历史输入及报告中的对应正文；不删除正式 Persona 或真实业务提案。已导出的外部备份需要自行删除。
- **导出用户备份：** 包含样例、反馈理由、附件、完整归属的测试集与报告，用于跨机器迁移。也可直接备份整个 `evaluations/` 目录。
- **导出评测数据：** 不包含反馈理由，也不包含可能引用理由的自动改进任务与子报告；用于离线分析，不直接作为反馈备份导入。
- **导入用户备份：** 校验附件 hash、样例修订、明确反馈与布尔标签对应关系；不覆盖同名样例、测试集或报告。进行中报告导入为中断，不调用模型，也不直接启用导入报告中的方案。自动候选可明确复制到手动草稿后重新检查。单文件上限 32 MB，单次最多 200 条样例；更大数据可按 API 的 `case_ids` 分批备份。导入来源标记是本地协议校验，不是对外部文件的人类身份认证。

样例会保存原必要对话和知识库快照，应当按私人数据保管；发送回测时可能包含个人信息。删除不会自动清除先前导出的文件或模型服务方已经接收的内容。

## 开发验证

```sh
PYTHONPATH=src .venv/bin/pytest -q
node --test tests/*.mjs
npm --prefix src/ai_persona/model_runtime test
# 临时演示服务，仅用虚构 Persona 和模拟模型，不读取真实账号：
PYTHONPATH=src .venv/bin/python tests/evaluations_smoke_server.py
```

演示服务地址 `http://127.0.0.1:8879/evaluations`。不要把演示中的反馈当成个人 benchmark。

统一 UI 与评测改版回归包括 Python、前端和模型运行时测试，以及桌面与窄屏浏览器检查。重点包括：反馈撤回、字段一致性、依赖级联、审核与反馈独立、历史输入保留、旧链接、模型预算确认以及迟到响应保护。测试服务使用一次性虚构 Persona，不修改真实数据或模型设置。

## 入口与保留规则

- 「设置」集中管理来源、独立能力开关、模型与数据保留；页面打开不自动安装 Hook、信任来源或启动后台。
- 旧 `/learning`、`/preferences/applications`、`/review` 链接保留具体任务／提案定位，转入统一工作台。旧写接口仍保留版本、归属和依赖校验。
- 材料来源引用仍可查看；对话学习只显示简短备注，不增加原始证据要求。
- 临时输入已清理时明确标示；仅在已有个人样例快照仍合法保留时使用该快照，不补读宿主会话，也不延长保留期。
- 审核答案暂未同步时显示已保存进度，可从对应样例重试读取；这不会撤销已发布 Persona 或已保存反馈。
- 从样例修改原反馈后，可返回原样例及筛选页码。审核不会自动跳页，编辑草稿只保留在当前页面内存；离页前有提示。
