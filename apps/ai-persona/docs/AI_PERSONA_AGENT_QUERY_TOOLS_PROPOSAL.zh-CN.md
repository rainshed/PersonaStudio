# AI Persona：Agent 查询工具公共契约

本文说明公开查询能力及设计边界，不包含任何个人工作区统计、私有记录链接或真实用户画像。参数与默认值以[工具注册代码](../src/ai_persona/query_mcp.py)和[结果契约](../src/ai_persona/query_contracts.py)为准；当前集成方式见[集成指南](../../../docs/INTEGRATIONS.md)。

## 设计原则

- 查询只读取已经生效的正式记录，不把待审核提案当成已知事实。
- 个人掌握程度、兴趣、说明和论文参与关系分别保留。来源中出现概念不代表用户掌握该概念。
- 先限定范围，再进行文字、语义和图关系召回；图扩展不要求邻居也包含原查询词。
- 返回足以解释关联的节点、关系与来源，明确分页、预算截断及不可用通道。
- 偏好维护查询与偏好触发分开；读取偏好不代表将它应用于本轮任务。
- 原文、备注和文件名是数据，不授予执行代码、读任意宿主路径或修改 Persona 的权限。

## 查询工具

| 工具 | 职责 | 主要输入 |
| --- | --- | --- |
| `get_knowledge_map` | 全局或局部知识地图，保留关系方向与个人状态 | `focus_ids`、`max_hops`、关系筛选、`scope`、版本、预算与游标 |
| `search_knowledge` | 文字、多语言语义和独立图扩展联合召回；支持结构化筛选 | `query`、实体类型、个人状态、材料类型、参与关系、`focus_ids`、`focus_mode`、范围与分页 |
| `get_persona_records` | 按稳定 ID 批量读取知识、课程、材料及可选证据 | `record_ids`、字段选择、`include_evidence`、版本与预算 |
| `list_source_files` | 浏览声明过的来源文件与可用表示 | 来源或材料引用、来源内路径、类型筛选、范围与分页 |
| `search_source_content` | 在指定来源或文件中定位原文片段 | `query`、`source_ids` 或文件引用、片段预算、范围与分页 |
| `read_source` | 读取文本、目录、图像或表格表示 | 来源/文件/证据/片段引用、`view`、`selector`、图像数量、范围与预算 |
| `search_preferences` | 为维护检索正式偏好、场景与样例，包括相应非启用状态 | `query`、`context_ids`、`statuses`、版本、预算与分页 |
| `get_preference_records` | 为维护按 ID 精读偏好、场景与样例 | `record_ids`、版本、预算与分页 |

知识检索回答“哪些正式记录相关”，文件内搜索回答“原文哪里相关”。来源可以属于材料，也可以属于已经提供引用的偏好样例，不要求每个来源都有材料记录。

## 统一结果

知识和来源查询返回 `ai-persona.query-result/v2` 结构：

| 字段 | 说明 |
| --- | --- |
| `tool`, `ok`, `request_id` | 操作身份与结果状态 |
| `persona_revision`, `scope` | 实际读取的正式版本与范围 |
| `data` | 本工具的节点、关系、命中、文件或片段数据 |
| `coverage` | 完整、部分或降级覆盖；预算与可继续读取信息 |
| `next_cursor` | 保持原查询条件继续读取的游标 |
| `warnings`, `error` | 可恢复限制与结构化错误 |

节点引用携带稳定 ID 与对象版本；关系保留端点、类型、方向、材料作用、重要性、说明和证据引用。检索依据不改写个人知识状态：`semantic_related` 是本次召回标记，不能解释成掌握程度或事实置信度。

## 范围与版本

`scope` 是当前工作区内的查询约束，不是独立账号或租户权限。省略范围查询当前允许的正式记录；显式空标签范围返回空，不回退全库。标签不明确的课程或材料不能仅凭标题猜测其领域。范围也约束关系中间路径、证据及来源。

一致读取应携带返回的 `persona_revision` 作为后续 `expected_persona_revision`。版本改变时重新取得引用，不把该字段当作任意历史版本选择器。分页应保持原查询、范围、预算与筛选；无效游标需要重新查询。

详细语义见[范围、版本与分页](AI_PERSONA_SCOPED_MCP.zh-CN.md)。

## 知识地图与搜索

不提供 `focus_ids` 时，地图返回允许范围内的概览。预算允许时交付完整紧凑图；超出时明确报告部分覆盖、领域或继续读取入口。没有关系的记录也必须可发现。

提供起点时，默认展开一跳，最大两跳。`focus_mode=prefer` 保留范围内独立召回并优先所选方向；`only` 严格限定起点及关系邻域。两种模式都保留起点的候选资格。

文字、语义与图关系是独立候选通道。只有真实的别名匹配才能标为别名命中；图扩展项应返回可解释的关系路径。搜索分数不表达用户熟悉程度。

语义嵌入在本机运行，模型文件首次使用时下载。相关缓存按来源与版本维护；语义通道不可用时返回降级覆盖，不能把文字结果称为完整语义召回。

## 来源阅读

工具只接受声明来源中的文件或不透明引用，不接受任意宿主绝对路径。读取前检查来源清单、文件哈希与允许范围。来源内目录也需要校验，不能通过路径穿越或符号链接读取其他数据。

`read_source` 根据实际支持的表示返回文本、图像或表格；图像通过 MCP image 内容块交付。目录型来源先列文件，之后选择具体引用。只有声明与支持的表示才可读取，不能假装完成未支持文件的解析。

行号和页码从 1 开始，文字偏移从 0 开始；不同表示的坐标不能互相猜测。分段读取使用返回的 `next_selector`；片段引用绑定文件内容和提取版本。覆盖说明应区分已读取原文、被截断部分与未支持内容。

## 偏好与提案

日常偏好触发沿用 `resolve_persona_activation` → `prepare_preference_context`。前者可调用配置模型，后者基于有效结果组装偏好包；失败或过期的激活结果不能伪装成有效偏好。

`search_preferences` 与 `get_preference_records` 用于检查和维护正式偏好，不自动触发场景、注入本轮偏好或修改记录。

修改继续通过 `propose_change_set` 形成待审核候选。MCP 不提供接受、拒绝或发布工具；人工审核在 Studio 完成。提案版本与依赖检查不能由查询成功替代。

## 合成用例验收

使用随包虚构 Demo 或独立临时数据，至少验证：

1. 无标签记录可在未限定范围发现，限定领域后保持边界。
2. 中文查询与英文概念能通过可用语义通道关联，降级时明确报告。
3. 图扩展保留正确方向和材料作用，不推断用户熟悉程度。
4. 文件、证据、偏好样例来源都按引用与范围读取；拒绝越界路径。
5. 分页、预算截断、版本改变与游标失效有明确结果。
6. 待审核变化不影响查询，发布后版本与结果同步改变。
7. 偏好维护查询不触发模型激活或修改正式记录。

相关自动化测试位于 `tests/test_query_tools.py`、`tests/test_query_retrieval.py`、`tests/test_scoped_mcp.py` 与 `tests/test_mcp.py`。通过这些测试不等于真实模型语义质量已全面验收；不发布个人工作区的实验记录作为公共测试证据。
