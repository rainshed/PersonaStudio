# 材料整理与知识图

本地实现日期：2026-09-10。对应单材料 Codex 提取及多材料知识图两阶段设计；代码在本仓库，尚不代表 GitHub Release 已发布。

English: open **AI Assistant → Read a paper → Extract knowledge from multiple sources** (`/extract`). Add arXiv links and Markdown/PDF/TXT files, customize the extraction rules, and run Codex. Results are proposals; review them before they change your knowledge base. The first extraction interface currently uses Chinese labels. Other application pages retain their existing language support.

## 使用流程

1. 在 AI 维护助手的「读论文，整理知识」卡片中，点击「同时从多篇材料中提取知识」。
2. 首次使用时连接 Codex。已有本机 Codex 登录可直接复用；也可在页面打开 ChatGPT 登录，或提交 OpenAI API key。认证完成后刷新登录状态。这里使用 Codex，不使用旧 AI 维护助手的模型路由；旧模块的其他平台能力继续保留。
3. 多行粘贴 arXiv 链接/ID，或一次选择多个 Markdown、TXT、PDF 文件；可以混合添加。检查清单、固定版本和解析警告。重复内容/相同 arXiv 版本自动排除；不同格式是否为同一论文不能总是自动判定，可在清单里明确关联。
4. 修改目标、知识点定义、关系规则和关注领域，选择提取结果语言（中文或英文，默认中文）；Codex 自主安排阅读。规则可以保存为下次默认值；本集合保存自己的规则快照。
5. 点击「开始 / 继续整理」。所有材料在同一轮任务内可用，Codex 自主决定阅读顺序、交叉检索和深入程度；检查点可选。页面显示实际读取位置，不把进度估计伪装成百分比。
6. 直接在结果下方的审核工作区选择知识点或关系；图谱与主页共用同一组件。掌握与兴趣可直接选择，其他内容按需编辑；支持逐项或勾选多项通过。关系依赖未选中时，会明确列出并加入选择，待用户核对后再次点击才保存。原文依据和技术详情默认收起。只有审核会修改正式知识库。

默认知识点规则：提取重要、可独立检索和复用的专有名词，优先已有领域和广泛使用的术语，复用已有节点，避免泛词与过度细分。新提出的有用术语应限定范围。新增节点数量是上限，不是配额。

## 读取、证据与状态

- arXiv 接受 `/abs/`、`/html/`、`/pdf/` 或 ID；固定具体版本后先尝试 HTML，保留章节锚点和公式文本。HTML 不可用时读取 PDF。需要视觉核对时，可按需下载同版本 PDF 并读取单页。
- 本地 Markdown 按标题组织，PDF 按页组织。原文件保持不变，另存稳定的结构化文本表示和行号。
- Agent 初始收到任务目标、规则、来源标识和应用生成的字段契约；通过工具按需检索和阅读。搜索命中不能直接当证据，必须读取有完整行号的片段。
- 保存的依据绑定来源 ID、版本、文件、行号及哈希；提交再次校验。不能引用未读、已改变或已移出结果的来源。
- PDF 图像只用于核对，不能冒充已抽取的文字证据。扫描件暂不提供 OCR；没有可靠文字依据的内容进入限制/待核对项。
- 不从上传、讨论或提取行为推断用户已读、喜欢、感兴趣或掌握某个知识点。

材料契约升级为 `ai-persona.material/v3`：`user_relationships: []` 表示未指定。读取已有 v2 记录时保留原关系并升级内存表示；已有正式文件不会因打开页面而被批量改写。后续正常保存使用 v3。新 schema 随构建输出，旧阅读状态继续可筛选。v1 不在本次迁移范围内。

## 失败、继续与增量

- 导入失败在输入旁显示；运行错误在运行控件旁显示并定位。某份材料失败不会清空其他材料的有效分析。
- 「重新分析」可单独重试一份材料；失败任务保留未完成的检查点。运行中的任务可停止，迟到响应没有写入资格。
- 「只整理成功部分」明确排除失败材料；排除项和未读章节仍展示在页面。
- 后续添加/移出材料或修改规则会产生集合修订。增加材料复用已有来源分析；修改规则需要重新分析。继续时重新读取已有知识版本。
- 上一修订仍有待审核提案时，先完成审核再生成下一版，避免对同一集合重复造点。旧提案链接保留，已有审核决定不会被覆盖。
- 进程中断后可恢复检查点。提案已经落盘但任务状态未写完时，按固定幂等键恢复原提案，不重复创建。
- 移出集合不会删除正式材料、知识或证据。备份时同时保留 `persona-data` 和 `persona-state`；后者包含整理任务数据库、检查点和按需下载的 PDF 核对副本。

## 当前预算与边界

| 项目 | 当前值 |
|---|---|
| 集合 | 最多 20 份有效材料，由 Agent 自主安排；同时运行 1 个集合 |
| 上传文件 | 每份最多 20 MB；PDF 最多 500 页；解析文本最多 8 MB |
| 读取 | 单次最多 200 行、约 18,000 字符；搜索和候选分页 |
| 时间 | 每轮集合任务默认 15 分钟，可设 1–60 分钟；达到预算保留检查点 |
| 工具调用 | 每轮最多 500 次 |
| 新知识点 | 默认最多 20 个，用户可设 1–100；结果允许新增 0 个 |
| 整合提交 | 最多 300 项变更、600 条内联依据，仍受现有 1 MB 提交上限约束；超限要求精简或延后，不截断结果 |

提案本身保留依赖分组，关系不能绕过尚未成立的端点。外部通用 MCP 的单次 50 项限制不变；本机批量整理通过应用内部入口使用更大的、有界提交预算。

不提供任意网页抓取、自动 OCR、无人审核发布、多个 Agent 后端或全领域知识图保证。跨材料综合判断、不能用现有关系类型准确表达的条件以及无直接证据的争议，保留为待核对项；语义合并质量仍需人工审核。

## 实现与验证

`extraction/contracts.py` 定义规则和输入输出；`repository.py` 保存任务与修订；`sources.py` 管理材料表示；`service.py` 调度、证据校验和提案；`backend.py` 是独立 Codex 适配器；`mcp.py` 提供每个任务/阶段独立的受限工具。

Codex 通过官方 Python SDK 接入。优先使用本机不低于 SDK 基线的 Codex，缺少时使用随 SDK 安装的固定运行组件；如果当前模型要求更新版本，页面会明确提示更新 Codex。组件安装由锁文件管理。任务使用专用工作目录，禁用 shell、网页搜索、宿主 MCP 和 Hook，注入内部任务标识，避免进入 AI Persona 对话学习；不复制账号密钥到任务目录。Demo 使用独立的 Codex 配置和认证目录。

继续操作从应用保存的检查点启动干净上下文，不依赖某个 Agent 私有的对话历史格式。后台启动/取消/状态与进度事件经过适配器和任务服务；未来替换执行后端时，可复用来源、规则、校验及审核服务。

验证包含：结构解析与来源定位、版本固定、重复和同文表示、旧任务全文覆盖兼容、PDF 页核对、伪造依据/个人状态阻止、单篇失败和部分提交、取消/过期阶段、幂等与提交后崩溃恢复、依赖审核、超过 50 项的内部批次、桌面/移动页面及就近错误。真实 Codex 对两份隔离测试笔记完成了 2 个知识点、2 份材料、3 条关系的 7 项待审核提案。该样本证明执行闭环可用，不代表长论文的质量、耗时或所有账号的登录都已得到验证。

离线功能回归：`uv run --no-editable --project apps/ai-persona --extra dev pytest apps/ai-persona/tests/test_extraction.py`。页面回归：`npm run test:extraction`。测试使用隔离工作区，不修改个人知识库，也不会自动登录或调用付费模型。

### 数量上限与遗漏说明

开始按钮旁会显示材料数与整个集合的新增知识点上限（默认 20，范围 1–100）。上限不限制已有节点复用、材料条目或关系数量。输入框不会随滚轮调整数值。开始时会核对页面上限与服务端保存值，并记录设置变化及本轮实际采用的上限。

结果中的「因数量上限暂缓的概念」逐项列出名称、原因和已读取的原文依据；这些条目不是正式知识节点。未报告遗漏不代表已穷尽全文。旧任务保留原来的文字说明。

### 自主执行与审核更新（2026-09-11）

固定的单篇分析→合并编排已替换为一次集合任务。保留原有阶段数据读取兼容，继续任务仍可使用已有来源检查点，但新任务不要求先提交单篇分析。普通 AI 维护助手也取消了长材料逐段调用模型的预分析，参考原文由工具按需提供。更新、来源证据、个人状态与人工审核的约束仍由应用校验。

变更组的 500 KB 原文预算按唯一的来源版本、位置和摘录计算；同一段文本被多个候选引用不重复扣减。每项提案仍保留可独立审核的证据快照，尚未迁移为跨记录共享的证据存储。

批量审核按依赖顺序逐项提交。若某项保存失败或结果不确定，停止后续提交并明确显示已完成数量；不自动重放写入。原文和技术记录保留，默认界面只显示面向审核的内容。

输出字段和关系类型由现有数据模型生成，并通过 `schema` 工具可查询。字段校验错误返回具体原因；失败提交不创建提案，修正后可完整重交。这是输出契约，不规定模型阅读的先后顺序。

### 四篇 arXiv 实测（2026-09-10）

按用户要求清除先前两轮提取产生的材料和待审核结果，未新建备份。通过实际 Studio 页面重新输入 2511.09629v1、2501.08381v3、2310.03069v2、2404.16927v2；复用已缓存的固定版本原文，由真实 Codex 重新读取并提取，默认总上限 20。

成功提交 79 项待审核变更：20 个知识点、4 篇材料、55 条关系（32 条材料覆盖、23 条知识关系）。从开始执行到完成约 207 秒。包含张量网络方法、玻尔兹曼方程和 Lévy walk；15 个因上限暂缓的概念逐项展示，其中包括 TEBD、DMT、NESS。附录和 PDF 页面未逐项核验；原文公式疑点保留为待核对说明。本次结果保留待审核，个人状态未设置。

验收发现并修复了重复证据的预算计算，以及输出契约缺失、字段错误过于笼统的问题。第二轮模型遇到读取数量超限及关系证据字段错误时自行修正，完整提交未删减候选；随后在契约中补充读取上限，并移除应由应用生成的 evidence_refs 字段。没有通过增加超时时间解决这些问题。

真实结果页面和收件箱均呈现 24 个节点、55 条边，复用主页组件。隔离的桌面/手机浏览器测试通过完整的上传、提取、个人状态选择、依赖核对、批量保存及主页展示流程。全量 Python 回归 770 项、JavaScript 单元测试 74 项通过；最后的输出契约调整另跑提取专项回归。

### 图中拒绝与结果语言

审核图谱中的待审核知识点带有“×”，点击即可拒绝该候选，并一并拒绝依赖它的待审核候选。操作结果显示在图谱附近；已拒绝节点淡化保留以供核对，已有正式知识不受影响。材料节点、已通过节点和主页图谱不提供该快捷拒绝按钮。保存失败会明确提示，并重新读取服务端状态，不自动重试写入。

“提取结果语言”控制新知识点名称、说明、关系解释及结果说明，中文和英文均可保存为下次默认值。具体任务保留语言快照；论文原名、书目信息、原文证据和已有记录名称不随之翻译，已有提取结果也不会自动翻译。必要时以别名保留原语言的通用术语。
