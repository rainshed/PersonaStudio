# AI 维护：直接进入待审核区

## 目标

取消“确认草稿 → 提交候选 → 再审核”的重复人工关卡。自然语言维护和材料整理采用同一规则：模型生成候选，程序校验通过后自动进入待审核区；只有用户在审核页批准，才改变正式 Persona。

内部草稿继续承担对话上下文、可选字段编辑和失败恢复职责，不是必须经过的审批页面。触发场景判定仍是只读功能，不受此流程影响。

## 用户流程

1. 在统一入口或记录／材料入口提出维护要求。
2. 程序读取相关记录与材料、调用模型、校验字段、版本、来源和依赖。
3. 有非空候选且没有待澄清问题时，自动创建待审核 ChangeSet，显示数量和“前往待审核区”。不再要求点击提交。
4. 有待澄清问题或没有变更时，留在对话；已有待审候选不会因此被撤回。
5. 用户可直接到审核页批准／修改并批准／拒绝／暂缓，也可继续对话或展开可选编辑。

继续维护的输出是当前任务的完整候选快照，不是追加操作。保存可选编辑也会自动更新待审核区。移除部分候选必须保留依赖；放弃整组须在审核页拒绝，不能用空输出默默撤回。

## 同一组候选的更新

- 保持 ChangeSet ID 和任务归属不变，`generation` 递增，审核入口 URL 稳定。
- 只有全组仍为 `pending_review` 才允许替换。批准、拒绝、暂缓、失效均阻止继续覆盖；用户应新建任务。
- 开始维护时检查一次，提交时在与人工审核共用的进程间锁内再次检查，防止模型运行期间的人工作出决定被覆盖。
- 新版本分配新的 Proposal 和候选记录 ID，依赖图随完整快照重建。旧 Proposal 标为 `stale`，注明系统替换并移到历史；旧 ChangeSet 快照保存到 `proposals/change-sets/history/`。
- 旧审核页面不能批准、拒绝或暂缓被替代的 Proposal。人工决定不会被改写。
- 旧版本没有任务归属字段的 AI ChangeSet，只通过原有 `ai-draft:{session_id}:` 幂等键识别归属。

## 持久化与恢复

候选首先在内存中完整构造校验，随后写入 `persona-state/pending-sync.json` 日志，再更新 Proposal 和 ChangeSet 文件。持有 `proposal_lock` 的审核写操作会先重放未完成日志；重放完成后才允许人工审核。该机制保证进程中断后可恢复，不声称多个文件对无锁读取者同时切换。

SQLite 会话状态：

| 状态 | 含义 |
| --- | --- |
| `running` | 模型分析中，保留已有待审组 |
| `ready` | 等待补充／没有变更；也兼容旧版完成草稿 |
| `submitting` | 正在同步待审核候选，不调用模型 |
| `submitted` | 候选已送入审核区；实际审核状态从 Proposal 读取 |
| `submission_failed` | 候选已保存，送审未完成，可无模型重试 |
| `failed` / `cancelled` | 分析失败／取消，可复用检查点继续 |

内容幂等键覆盖草稿、Persona 基线和来源。送审重试若发现该版本已提交，直接恢复会话状态，不另建候选。部分文件写入中断时重放日志完成同一版本。程序校验失败不发布记录；提交失败也不会要求模型重新生成。

`POST /api/ai/sessions/{id}/submit` 保留为失败重试和旧版草稿兼容入口，需要当前会话版本及原有本机请求保护。普通流程由后台自动调用。`edit` 自动同步有效候选，`message`／`resume` 的成功结果也自动送审。

备份应同时包含 Persona 数据和状态目录；恢复前停止 Studio。日志和草稿可能包含私人候选及证据，不能当作可公开的运行日志。

## 不做的事情

- 不自动批准，不绕过依赖、来源或正式记录版本检查。
- 不批量提交全部历史草稿；旧草稿可使用兼容入口。
- 不改变模型连接、账号、选模、材料分析预算和场景判定接口。
- 不覆盖任何已有人工审核决定，不删除旧候选历史。

## 验收

覆盖自然语言／材料自动送审、澄清问题、空输出、同组替换和历史、旧审核表单、候选移除、任务归属、生成期间人工审核、构造失败、写入中断重放、并发提交及无模型重试。正式 Persona revision 只能在人工批准后增长。

2026-09-07 验收：208 项 Python 测试、19 项模型适配层测试通过；Ruff、JavaScript 语法与差异检查通过。隔离 Studio 验证了材料恢复后自动送审、折叠的可选编辑、保存后同组更新和审核页返回任务入口。

旧草稿兼容：关系记录 Schema 中的 `values.evidence_refs` 会规范到提案层 `evidence_refs`，保留并校验所有引用，不丢弃真实证据、不放宽未知字段规则。对应空列表与无效引用均有回归测试。当前材料任务的 10 条既有候选已通过无模型送审迁移，正式 Persona 保持 R119；没有批量提交其他历史任务。
