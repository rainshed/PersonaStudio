# AI Persona：根据用户材料生成轻量初稿

版本：v0.5 · 日期：2026-09-03

阅读对象：执行初始化的 Agent，以及向 Agent 提供接口的接入方。

本文约定材料初始化的目标流程。当前代码尚未实现完整的 Agent 初始化接口；执行前必须读取实际接口、Schema 和目标工作区。本文中的步骤和候选结构不是可直接调用的 API。

## 1. 目标与边界

根据用户主动提供的材料，生成一份语言一致、结构清楚、可在 UI 中修改和确认的轻量初稿。

```text
读取材料 → 建立材料清单 → 筛选少量知识点 → 检查语言、粒度与重复 → 提交提案 → 用户在 UI 审核
```

初始化首先准确记录材料，其次才筛选值得长期维护的知识点。材料中出现的主题不会自动成为用户知识点；初稿不追求覆盖所有术语，也不追求一次完成完整人格。

本轮可以产出：

- 去重后的材料候选；
- 少量、有个人相关性且可复用的知识点；
- 材料与知识点之间有依据的关系；
- 用户已经明确提供的个人属性。

默认不产出完整学科树、推测的课程或写作与任务偏好。掌握程度、兴趣、材料理解程度和个人掌握范围可以以后补充。

## 2. 职责和输入

| 参与方 | 职责 |
|---|---|
| Agent | 读取材料，识别语言和重复项，生成候选，完成质量检查，提交 AI 提案并提供 UI 入口 |
| 用户 | 在 UI 中查看、修改、接受、暂缓或拒绝候选，决定最终内容 |
| UI 与后端 | 展示类型、来源和差异，校验格式、版本与依赖，发布用户确认的内容并保留历史 |

Agent 不执行人工审核，不调用接受、拒绝、暂缓或发布接口，也不根据聊天中的“可以”替用户确认。去重、来源核对和质量检查属于提交前处理，不构成人工批准。

执行前读取：目标工作区、本轮材料、已有正式记录和待审核提案、实际可用接口、当前 Schema，以及用户已经明确给出的语言或范围偏好。已有信息直接使用，不重复询问。

## 3. 强制提取规则

### 3.1 输出语言跟随输入材料

语言按每份独立材料判断，不能根据对话语言、UI 语言、文件夹名称或 Agent 的默认语言统一翻译。

| 内容 | 语言规则 |
|---|---|
| 材料标题 | 保留原始正式标题，不翻译、不重写 |
| 材料内容摘要 | 使用材料正文的主要语言 |
| 知识点名称和知识说明 | 使用其主要依据材料的语言 |
| 其他语言名称 | 只在确实有用时放入 `aliases` |
| 专有名词、缩写和模型名 | 保留领域中的规范写法，例如 TEBD、PXP、Lindblad |

若一个知识点来自多种语言的材料：用户指定语言时遵从用户；否则使用最主要、证据最强的材料语言，其他语言的规范名称放入别名。无法确定主要依据时保留草稿，不自行选择对话语言。

同一字段内避免中英文句式混杂。翻译后的短语只有与原名称语义等价时才是别名，不能为了凑别名制造新术语。

### 3.2 材料事实与用户知识分开

| 信息 | 处理方式 |
|---|---|
| 材料自身的标题、论点、方法和结论 | 写入材料摘要或材料关系 |
| 用户明确陈述的经历、程度或兴趣 | 保留原意及来源，可形成人格属性候选 |
| 值得长期维护且有个人相关性的概念 | 通过第 3.3 节门槛后才创建知识点 |
| AI 对用户的推测 | 不写成人格事实 |

“文章讨论某主题”只证明材料与主题有关，不证明用户掌握、喜欢或希望长期维护它。论文署名不代表用户独立完成全部理论、实验和代码；正文中的“我们”不能直接改写成当前用户。

### 3.3 知识点必须通过准入门槛

一个候选只有同时满足以下条件，才进入初始化知识点清单：

1. **可复用**：它是能跨材料或未来任务复用的领域、概念、理论、模型、方法、技术或工具，不是论文标题的改写。
2. **个人相关**：材料明确关联用户的工作、项目或经历，或者它在多个独立材料中反复成为核心内容。重复格式副本只算一份。
3. **核心而非顺带出现**：它是研究对象、核心机制或实际使用的方法，不是背景术语或参考文献。
4. **可独立解释**：不提“本批材料”也能说明它是什么、解决什么问题或用于哪里。
5. **不重复**：规范名称、缩写、翻译和别名均已与正式记录及待审核提案比较。

仅在一篇阅读材料中出现、且没有其他个人相关性证据的主题，默认保留为材料主题或关系，不创建用户知识点。无法确定时宁可不创建，以后补充的成本低于审核和清理噪声。

初稿没有知识点数量指标。不能为了达到 5 个、10 个或覆盖每份材料而放宽门槛。

### 3.4 一个节点只表达一个概念

标题含“与”“及”“和”时，必须检查是否误把多个概念捆绑在一起。只有整体本身是稳定术语时才保留组合名称。

- “Tensor networks and TEBD”应考虑拆成 `Tensor network`、`Matrix product state` 和 `Time-evolving block decimation`；
- “PXP model and Rydberg-chain dynamics”应分别检查 `PXP model`、`Rydberg blockade` 和 `Quantum many-body scar`；
- “Open quantum systems and dephasing”应区分领域与具体机制。

拆分不表示所有子项都要创建；每个候选仍须单独通过准入门槛。

为节点选择最具体的 `semantic_role`：`domain`、`area` 用于学科或方向；`topic`、`concept` 用于主题、现象或基础概念；`theory`、`model` 用于理论框架或模型；`method`、`technique`、`tool` 用于方法、实现技术或工具。不能因为不确定就把几乎所有节点都标成 `topic`。

### 3.5 知识说明必须自包含

知识说明用一至三句话回答：它是什么、解决或描述什么问题、关键机制是什么、通常用在哪里。移除本轮材料后，说明仍应成立。

禁止在知识说明中写入：

- “本批包括”“本批聚焦”“根据本次材料”等批次描述；
- 用户精通、喜欢或参与了什么；
- 文件名、章节、行号、绝对路径和提取过程；
- 审核提示、免责声明和 Agent 工作记录；
- 多篇材料内容的拼接摘要。

当前模型用 `summary` 存储知识说明；Material 的 `summary` 表示内容摘要。`scope_note` 只记录个人掌握范围，Markdown 正文只记录用户自己的笔记。用户没有提供笔记时正文留空，Agent 不把来源或审核记录写入个人笔记。

### 3.6 来源进入依据字段

每条候选保留简短、可核对的依据：来源对象、章节、页码、行号或短摘录。来源信息放入提案 `reason`、Evidence 或专用来源关系中，只使用稳定 Source ID、相对位置或可移植引用，禁止保存用户设备上的绝对路径。

来源支持什么，就只据此提出什么。“正文使用 TEBD”支持材料与 TEBD 的关系，不支持用户掌握程度。没有稳定定位时保留来源名称和章节，不伪造 ID、页码、行号或哈希。

AI 提案必须保留 `submitted_by="ai"`，并在 `reason` 中简短说明候选为何通过准入门槛及其主要依据。`reason` 不重复整份材料清单，也不进入个人笔记。

### 3.7 个人属性允许未设置

没有明确依据时，掌握程度、兴趣、材料理解程度、喜欢程度和掌握范围保持未设置。不得用 `aware`、`low` 或 `skimmed` 代替未知；文件夹名称、出现次数、署名和材料难度不能单独决定个人属性。

当前实现用 `unspecified` 表示知识点、课程和材料未设置的 `knowledge_level`。兴趣与材料喜欢程度使用各自字段的 `unspecified`。不要向枚举传入 `null` 或空字符串。材料阅读关系仍须满足独立约束。

## 4. 执行流程

### 步骤一：读取现状并建立材料清单

读取目标工作区、正式记录和待审核提案。已有内容时执行增量初始化，不清空、不重新初始化，也不覆盖用户确认过的属性。

为每份输入记录：可读状态、主要语言、材料类型、规范标题、重复项和用户明确说明的关系。只读取用户提供的范围，不因简历提到项目而扫描其他目录，也不因论文引用文章而导入参考文献。

### 步骤二：去重并生成材料候选

比较标题、作者、标识符、内容和版本。同一论文的 PDF、Markdown、OCR 或转换副本通常形成一个材料条目；转换副本不增加证据权重。有实质修订的版本保留版本差异，不直接覆盖。

材料候选先于知识点生成，包含原始标题、材料类型、原语言摘要和来源。先阅读标题、摘要、引言、结论和必要的方法段落。不可读文件使用已提供的读取能力或可读副本；部分失败时继续处理其余材料，不能只凭文件名编造摘要。

### 步骤三：建立知识候选池

从去重材料中收集核心研究对象、概念、理论、模型、方法、技术和工具。此时只形成候选池，不直接提交。

每个候选记录：规范名称、来源语言、必要别名、`semantic_role`、自包含知识说明、个人相关性依据、涉及它的独立材料，以及可能重复的已有节点。

### 步骤四：筛选、拆分并建立最小关系

逐个执行准入门槛，移除只代表单篇文章主题的候选。检查组合标题，将领域、模型、方法和技术拆开，再分别判断是否保留。

对保留节点做跨语言去重，以主要依据材料的语言作为主名称，其他语言放入别名。只建立明确且有用的关系，例如：

```text
Tensor network  ──broader_than──>  Matrix product state
Time-evolving block decimation  ──requires──>  Matrix product state
Material  ──covers / method──>  Time-evolving block decimation
```

首次初始化不补全完整学科树；没有可靠关系时允许节点暂时独立，但不能把所有内容长期保留为同一层的 `topic`。

### 步骤五：执行提交前质量检查

每个知识点必须全部回答“是”：

- 主名称和知识说明是否使用主要依据材料的语言？
- 其他语言是否只放在必要别名中？
- 是否通过可复用、个人相关和核心内容门槛？
- 标题是否只表达一个稳定概念？
- `semantic_role` 是否准确？
- 知识说明是否脱离本轮材料仍然成立？
- 是否与已有记录和候选完成跨语言去重？
- 来源是否在依据字段，并且没有绝对路径？
- 个人笔记是否只包含用户提供的笔记？
- 未知个人属性是否保持未设置？

任一项为“否”时不提交。先修正、拆分、合并，或者只保留材料及其主题关系。

### 步骤六：保存草稿或提交提案

按实际接口校验候选。相同输入重试时复用已有草稿或提案；提交结果不确定时先查询，不重复创建。

材料、知识点和关系存在依赖。接口支持同批临时引用时按其规则提交；不支持时保留关系草稿。Agent 不能通过自行接受端点提案绕过依赖。

提交只产生未生效提案，不直接写入正式记录、快照或索引。AI 不冒用人工身份，不调用审核决定和发布接口。

### 步骤七：引导用户在 UI 审核

展示简洁概览：独立材料数量、通过门槛的知识点、未提交的低置信候选和未设置属性。提供实际可用的 UI 入口，不默认展示 JSON、绝对路径或长篇推理。

用户可以修改名称、别名、知识说明、角色和个人属性，并接受、暂缓或拒绝候选。发现组合或重复节点时，应拆分、合并或拒绝后重新生成。当前 UI 不支持专用拆分、合并时，Agent 必须说明限制，不能把普通字段编辑描述成这些能力。人工备注不是必填项。

### 步骤八：按需读取审核结果

UI 发布后即形成有效版本，不依赖 Agent 再次确认。用户要求查看时只读查询，只汇报实际生效内容。部分通过时区分已发布、待审核、暂缓和拒绝；不自动重提被拒绝候选。

## 5. 信息不足和纠正已有初始化

| 情况 | 处理方式 |
|---|---|
| 无法确定材料语言 | 检查正文而非文件名；仍无法确定时保留草稿 |
| 多语言来源且无主要依据 | 遵从用户偏好；没有偏好时保留草稿 |
| 只有一篇阅读材料支持某主题 | 保留为材料主题或关系，默认不创建用户知识点 |
| 不知道程度、兴趣或贡献 | 留空，继续处理其他字段 |
| 没有 UI 审核入口 | 保留未生效内容，不改用聊天批准或由 Agent 发布 |
| 不支持候选依赖 | 保留关系草稿，端点经用户发布后再提交 |
| 不支持拆分或合并 | 不伪造能力；拒绝问题候选后重新提出原子化候选 |

纠正已有结果时，先读取正式记录、待审核提案和人工修改。对待审核问题候选形成替代草稿，不自行拒绝；对已发布问题节点使用更新、关系调整或归档提案，不直接改正式文件。保留用户已填写的程度、兴趣、范围和笔记，语言变更和节点拆分同样交回 UI 审核。

## 6. 正反例

假设输入是一篇英文论文，正文主要讨论 TEBD。

错误候选：

```text
名称：张量网络与 TEBD
知识说明：本批材料涉及 MPS、TEBD、TDVP 和 Lindblad 稳态。
个人笔记：来源于 /path/to/input/paper.pdf，第 12–20 行，待用户审核。
```

它翻译了英文来源、合并多个概念、把材料批次摘要当作知识说明，还把绝对路径和审核记录写入个人笔记。

较好的候选：

```text
Name: Time-evolving block decimation
Aliases: TEBD；时间演化块消减（可选的其他语言别名）
Semantic role: technique
Knowledge explanation: Time-evolving block decimation is a tensor-network algorithm for approximating the time evolution of one-dimensional quantum many-body states represented as matrix product states.
Mastery level: unspecified
Interest: unspecified
Personal notes: 留空
Proposal rationale: 该方法是用户项目材料实际使用的核心数值技术；依据引用稳定的 Source 和章节位置。
```

只有 `Tensor network` 和 `Matrix product state` 也分别通过门槛时才创建节点并建立关系。若 TEBD 只在一篇普通阅读材料中出现，则只记录材料主题，不自动创建用户知识点。

## 7. 当前实现与接入要求

| 项目 | 当前状态 | 接入处理 |
|---|---|---|
| 空工作区初始化 | CLI `init` 创建空工作区，不执行材料提取 | 与本文的材料初始化区分开 |
| Agent 初始化接口 | 尚无完整的 LLM 提取、批次草稿和结果查询接口 | 接入方提供实际能力 |
| 输出语言 | Schema 接受多语言文本，没有语言一致性校验 | Agent 执行第 3.1 节；后续增加语言元数据与校验 |
| 掌握／理解程度 | 知识点、课程和材料支持 `unspecified` | 无依据时省略或使用 `unspecified` |
| 材料阅读关系 | `user_relationships` 当前非空 | 状态不明时需要草稿层支持，不能填虚假关系 |
| 知识说明与笔记 | UI 已分开，后端未阻止来源写入正文 | Agent 执行第 3.5、3.6 节；后续增加字段校验 |
| 审核编辑 | UI 支持常用字段修改后接受，人工备注可选 | 用户在 UI 审核，Agent 只提交和查询 |
| 拆分与合并 | 当前没有专用操作 | 拒绝问题候选后重新提交原子化候选 |
| 批次与依赖 | 以单项提案为主，关系要求端点已存在 | 不支持时保留关系草稿 |
| AI 身份 | 记录创建和更新可标记 AI；关系方法仍默认人工 | 接入层保证真实身份 |
| PDF 读取 | 内置提取主要支持文本、Markdown 和 HTML | 使用接入方的 PDF 能力或可读副本 |

审核决定和发布能力只供接收用户 UI 操作的后端使用，不开放给 Agent。
