# 对话学习：使用与平台接入

## 当前实现

用户消息 → 本机持久队列 → 信号识别 → 匹配已有 Persona → 候选整理 → 在对话学习页或待审核区审核 → 人工批准后生效。

偏好从具体行为要求、纠正和反馈中发现；知识从用户的 note／讲解请求中发现；关系连接新增知识与已有知识。无需重复多次，无需证明已经掌握，也不批量收集 AI 回答自行引入的知识。三类候选都只有简短备注（最多 300 字符），不生成聊天 Source／Evidence，不显示模型置信度。

判断先区分“用户要求 AI 怎样协作／呈现”与“本次要求修改什么产品功能”。按钮、字段、功能规格和单纯提交指令不会自动变成个人偏好；“符号首次出现给出定义”等可复用质量要求仍可一次触发。请求解释知识并整理为 note，只说明本次交付形式，不另推断“偏好 note”。前文只用于解析当前请求的指代，“继续／完成／提交”不会继承前文的学习意图。候选整理还会复核信号，错误信号可以直接丢弃，不必生成待审核记录。优化与小规模验证记录见[提示词优化记录](AI_PERSONA_CONVERSATION_LEARNING_PROMPT_OPTIMIZATION.zh-CN.md)。

接收与分析分离：Hook 的学习分支只入队，不调用学习模型、不注入对话上下文。两阶段分析复用现有 Pi 模型服务，任务名称为 `conversation_signal` 和 `conversation_candidate`，分别使用「对话学习判定」和「对话学习生成」的模型配置。偏好场景判定另行选模，主动维护与材料分析统一使用 AI 维护助手模型；材料整理原有证据要求不受影响。

## 从 Studio 开始

1. 更新正在使用的 AI Persona 安装，并重启 Studio 和模型服务，避免旧服务不认识新任务。全局安装与项目虚拟环境是两个入口，更新步骤见 README。若以前已启动学习 Worker，也先停止它再更新。
2. 打开「设置 → 应用接入」（`/settings?tab=sources`），添加应用、启用来源并配置接收范围：默认「仅指定项目／会话」，也可明确选择「所有本机 Codex 会话」。对自己的接入可开启「信任此连接的用户消息，跳过逐条来源确认」。默认采集、模型外发与来源信任均关闭，旧配置不会自动变为信任。Codex 还需按下文生成、安装 Hook 并完成宿主信任。
3. 在「模型设置」为「对话学习判定」和「对话学习生成」选择连接，或跟随默认模型。判定阶段可以单独配置快速模型，生成阶段优先理解与推理能力。
4. 在「设置 → 自动功能」确认外发范围和每日预算，选择「自动学习」并保存，再点击「启动后台处理」。选择「仅接收」只入队，不进行模型分析。后台不依赖页面保持打开，不随系统登录自动启动。
5. 左侧最近任务显示用户输入摘要、触发判断、反馈状态和审核进度；点击标题在右侧查看输入、反馈与候选，不再打开详情抽屉。小屏单独显示列表或详情，使用「返回列表」切换；「上一条／下一条」连续处理任务。

### 任务浏览与反馈

- 列表直接显示「未反馈／已反馈·满意／已反馈·不满意」，选中任务后在详情点击「满意／不满意」。评价的是本次**是否应该触发学习**，不评价生成内容；只有明确点击才保存个人测试样例。尚未形成有效判断的任务不能评价。
- 误点后可直接点击「取消反馈」，也可以改选。取消只撤回有效回测资格，不取消任务、不删除候选、不回滚 Persona；重新评价仍使用同一条样例。彻底删除历史数据继续在「反馈与测试样例」中操作。
- 不满意理由选填，单独点击「保存理由」，仅用于提示词改进、不参与回测。自动刷新和切换任务不会覆盖理由草稿；刷新或离开页面会提示尚未保存的内容。
- 候选直接在详情中「通过」「拒绝」或「编辑全部属性 → 保存并通过」，不必跳到其他页面。「更多属性」包含别名、标签、范围、备注等；掌握与兴趣只能由你填写，AI 不推断。来源引用和系统身份信息只读。只修改标题不会覆盖未编辑的其他属性，成功后重新显示后端保存值。
- 知识／场景与关系／偏好有依赖时，先审核被依赖项；拒绝父候选会明确提示关联拒绝范围。两处审核共用记录，候选在另一处已处理时禁止旧页面重复保存。审核不会代替你点击触发反馈；只有已明确反馈的样例才使用审核通过内容作为内容标准答案。
- 编辑草稿只在当前页面内存保留，切换任务后可继续编辑；离开页面会提示未保存。已审核的记录在本页只读，继续修改请使用对应 Persona 记录的正式编辑入口。
- 每页 20 条，搜索用户输入或来源名称；反馈状态、处理状态和来源可以组合筛选，覆盖全部历史任务而非最近 100 条。自动刷新只更新当前行；新任务通过提示按钮载入。在「未反馈」筛选中刚评价的任务暂留原位，点击「刷新列表」、翻页或重新筛选后再移出。
- 可用 `/learning?event=<任务ID>` 直接打开指定任务；到审核页再返回时恢复任务浏览状态。旧任务的正文或结果已清理时明确显示不可用，不自动补造反馈。重试的新运行不沿用旧结果的满意度，旧反馈可在详情中的「历史结果／反馈」查看。
- 配置分别收纳在「设置」中的「模型设置／应用接入／自动功能／数据管理」，需要明确保存才生效。打开或关闭面板不改变采集、来源信任、模型分析和后台启停状态。

完整页面规则见[页面改版设计](AI_PERSONA_CONVERSATION_LEARNING_PAGE_DESIGN.zh-CN.md)。

后台启停使用同一个按钮：状态为「已停止」时显示「启动后台处理」，「运行中」时显示「停止后台处理」。启动与停止过程中显示对应状态并禁用重复点击；以后台实际状态为准，不把请求成功当作已经启动或停止。未启用对话采集时不能启动，但已在运行的后台仍可停止。

停止后台会等待当前任务结束，页面显示「正在停止」；如要阻止当前任务送审，应取消该任务或关闭模型分析。关闭采集不会删除已经生成的候选。取消／撤回会将尚未审核的关联候选标为失效，不修改已经批准的正式记录。已经发出的模型请求可能继续消耗额度，但迟到结果不能绕过取消状态写入待审核区。

新知识与关系分别审核。依赖的新知识未批准时，关系不能生效；拒绝关系不影响独立知识。完全相同的已存在、待审、暂缓或拒绝候选会被抑制；新信息或语义变化由模型结合审核历史判断。首版相同知识标题／别名的重复“新建”保守跳过，需要明确更正已有节点时使用“更新”或主动维护。

## Codex：按步骤安装并验证

当前 Studio 仅提供本机 Codex 接入。首次打开「设置 → 应用接入」会显示五步引导，已有来源使用「编辑接入设置」或「安装与验证」继续配置。

1. **接收范围**：选择指定项目／会话，或所有本机 Codex 会话；填写名称、来源开关与输入确认方式。全局范围不包括远程主机或云任务。
2. **会话前文**：推荐读取当前会话的有限前文。页面检测当前 `CODEX_HOME`（未设置时为 `~/.codex`）下的 `sessions` 目录并展示路径，点击保存后才授权读取。手动目录及自定义 Codex 配置目录收在高级项。也可选择仅使用本次输入；留空不会自动读取默认目录。旧来源的读取选择保持原值。
3. **安装接入**：页面展示目标 `hooks.json`、当前文件状态及本连接的配置片段。点击安装会保留其他事件、其他来源及其处理器，只新增或更新本工作区、本连接的统一命令；修改前备份原文件，重复安装不重复添加。文件损坏、符号链接或预览后被修改时停止并提示。`config.toml` 中的 Hook 仅提示检查，不代为修改。也可复制片段手动合并。历史独立学习／偏好 Hook 应按原说明手动替换，避免重复。
4. **验证接入**：在 Codex 中审查并信任 Hook（CLI 可使用 `/hooks`；参见 [Codex 官方说明](https://learn.chatgpt.com/zh-Hans/docs/hooks#审查并信任钩子)）。生成一条 15 分钟有效的测试消息，发送到范围内的本机 Codex 会话。页面分别显示真实接收、范围匹配和前文读取结果。测试在自动功能关闭时也能进行；AI Persona 不调用学习或偏好模型、不入队、不保存测试正文。Codex 本身仍会正常回复。
5. **启用功能**：验证通过后，页面提供模型设置和自动功能入口。学习需要选择运行方式、保存并启动后台；偏好应用独立选择来源并启用。引导不自动改变功能开关或 Codex 的信任状态。

验证信息仅保存短期测试标识、时间、来源配置摘要、范围结果及上下文读取状态／条数，不保存前文。修改来源配置后旧验证失效；重新安装改变 Hook 定义时清除旧验证，需重新审查并测试。配置命令固定 Python、源码、数据／状态／队列路径，不依赖 Codex 的当前工作目录。命令行仍可只生成配置片段：

```bash
ai-persona learning hook-config --connection <来源ID>
ai-persona learning status
ai-persona learning start-worker
ai-persona learning stop-worker
```

多工作区时给命令显式传 `--data <persona-data绝对路径> --state <persona-state绝对路径>`。源码运行可用 `PYTHONPATH=src .venv/bin/python -m ai_persona` 替代 `ai-persona`。

### 所有本机 Codex 会话

1. 在「设置 → 应用接入 → 编辑接入设置」编辑你的 Codex 来源，将「接收范围」切换为「所有本机 Codex 会话」，保存来源。不需要把 `/` 加进允许项目列表。
2. 若尚未安装用户级 Hook，在引导中安装接入配置，或将配置片段手动合并到当前 Codex 配置目录的 `hooks.json`（默认 `~/.codex/hooks.json`），并完成宿主信任。不要覆盖已有 Hook，也不要重复安装同一条命令。若同一来源的 Hook 已配置好，切换采集范围不会改变命令，无需重新生成。
3. 采集总开关、来源启用、模型分析开关和后台处理仍独立控制；选择全局范围不会自动开启这些开关，也不会安装 Hook。更新代码后需重启 Studio 与已运行的学习 Worker，避免旧进程继续使用旧范围逻辑。

这里的“全局”是此来源收到的、本机当前用户且加载了该用户级 Hook 的 Codex 会话新消息，包括其他项目、worktree 和无项目会话。它不回扫历史，不自动覆盖远程主机、云任务、其他系统账号或使用另一配置目录的实例，也不意味着生成的偏好都适用于全局。

已保存的项目和会话列表在全局模式下暂不参与过滤，但不会删除；切回「仅指定项目／会话」后重新生效。队列任务在模型调用和送审前重新检查最新范围，超出新范围的任务会暂停；已发出的模型请求不能撤回，但迟到结果不能越权送审。会话目录的读取限制、来源信任策略、人工审核及预算限制分别控制；不要为了全局采集而扩大文件读取根目录。

接口字段为来源连接的 `scope_mode`：`restricted`（默认）或 `all`，不是消息事件字段，事件不能自行申请全局权限。该字段也适用于其他平台的标准来源。旧配置缺少它时保持限定范围；旧的 `allow_all_conversations` 只保留标准事件在无 scope／会话限制时的兼容行为，不会自动迁移成全局。

### 信任来源与严格模式

在「设置 → 应用接入 → 编辑接入设置」勾选「信任此连接的用户消息，跳过逐条来源确认」，保存即可，无需修改或重新安装 Hook。也可以在待确认任务详情点击「信任此来源并继续」。这是一次来源级选择，不是每条任务都要做的确认。

- 开启后：该来源的用户消息即使 `origin=unknown` 也能继续生成候选并进入待审核区；非用户消息、明确标为 `automation` 的消息和疑似凭据仍会被过滤。
- 现有任务：保存时将该来源中仍在允许范围、正文尚未清理的 `waiting_origin` 任务重新排队，复用已有信号检查点。不会重启已取消、已完成或失败任务，也不修改其他来源。关闭中的来源不会恢复任务。
- 保留边界：不改变采集、模型外发、后台启停、预算、文件读取权限及最终审核。开启信任可能因继续候选分析而消耗模型额度；不会自动发布 Persona。
- 关闭后：回到严格模式，未验证来源的有价值输入需要确认。仍可选择「仅确认本条为人工输入」，不影响整个来源；正在执行的任务也会重新检查策略，迟到结果不能绕过信任撤销。
- 真实记录：原消息 `origin` 和采集端 `verified_human_origin` 保持不变，不把用户选择信任伪装成事实验证。任务详情以 `origin_basis=trusted_source` 显示「按来源信任设置继续，未验证人工输入」。

平台无关接口字段是 `SourceConnection.trust_user_messages`，默认 `false`。它不是事件字段，不能由模型在事件中自行授予权限。保存来源的 HTTP 回执新增 `resumed_events`，表示此次重新排队的任务数。信任作用于该来源连接收到的允许用户消息，应仅为自己管理的接入开启。

### 当前限制

当前限制必须保留：

- 当前适配器未获得可靠的人工来源标识，Codex 消息保留为 `unknown`。开启来源信任后不再逐条确认；严格模式才停在“待确认输入来源”。信任模式可能产生少量来自未识别自动输入的候选，由最终人工审核把关。
- 原生事件 ID 与追加输入的区别仍受宿主字段限制。统一入口以来源、会话、turn、规范化工作目录和原始提示识别重传，第一次入队的背景固定；会话文件追加内容不会再次入队，新 turn 中相同提示仍视为新输入。无法区分同一 turn 中两次文字完全相同且无额外序号的原生输入。
- 会话 JSONL 是兼容解析，不是稳定平台 API。只读取允许目录中的有界消息，排除工具输出与分析通道；缺失、格式变更、跨会话或危险路径均降级。
- 已完成协议样本、失败放行、隔离模型链路与统一入口验证；学习回执和正文不进入 stdout，只有成功准备的偏好会返回给宿主。每台机器均须确认真实客户端已加载并信任统一入口，再进行端到端验收。

统一入口只读取一次正文和必要背景，再将学习事件交给独立进程入队。入队进程最多运行 3 秒，不阻塞偏好判断；学习模型继续由现有后台 Worker 处理。偏好应用有独立开关和默认 5 秒的本轮预算。参见[偏好应用说明](AI_PERSONA_PREFERENCE_ACTIVATION_USAGE.zh-CN.md)。

协议依据：[Codex Hooks 官方文档](https://learn.chatgpt.com/docs/hooks)。入队失败只输出不含聊天正文的安全诊断，退出码为 0；它不是保证磁盘故障时绝不丢失消息的机制。

## 开发接口：标准事件入口（当前页面仅开放 Codex）

新平台只需做消息、来源身份和上下文的规范化；核心不解析平台路径。来源连接的 `adapter` 可自定义，私有配置放 `adapter_config`，不发送给模型。平台凭据与远程身份认证由受信任连接器管理，不从事件自报字段获取授权。

先在 Studio 创建标准来源，或通过 `learning configure` 的 stdin JSON 注册 `settings`／`connections`。配置声明 `verified_human_origin=true` 只能用于确实能验证人工来源的本机连接器，不能根据 user 角色或 LLM 判断随意设置。

标准事件示例（替换来源、范围、会话及消息 ID 后使用）：

```json
{
  "schema": "ai-persona.conversation-event/v1",
  "event_id": "event-001",
  "source_connection_id": "my-connector",
  "event_type": "message.submitted",
  "conversation_id": "chat-001",
  "scope_ref": "project-a",
  "message": {
    "id": "message-001",
    "revision": "1",
    "role": "user",
    "origin": "human",
    "content": [{"type": "text", "text": "帮我生成一份关于贝叶斯更新的 note"}]
  }
}
```

```bash
ai-persona learning ingest --connection my-connector < event.json
ai-persona learning worker --once
```

CLI 接收成功返回 `accepted` 和内部事件 ID。重传保持原 event_id／消息版本；相同键不同内容被拒绝。修改／撤回要求来源声明版本能力；首版由适配器按发生顺序提交不透明版本，不宣称服务端能重排任意乱序版本。迟到的 submitted 不能覆盖已更新消息，撤回后不能重新激活同一消息 ID。

需要上下文时可随事件附 `snapshot`，其中来源、会话和 boundary 必须匹配事件的 `context.boundary`。核心最多一次补充识别上下文、一次补读 Persona 记录；仍不充分则等待，不扫描整个聊天。实现受控历史读取时注册 `ContextProvider`，没有注册的上下文引用不会被当作文件路径或 URL 打开。

其他传输复用同一应用服务：

| 接口 | 用途 |
| --- | --- |
| `POST /api/learning/v1/events` | 本机标准事件入队，成功 202 |
| `GET /api/learning/v1/events/{id}` | 本机任务详情 |
| `POST /api/learning/v1/events/{id}/context` | 给等待中的事件补充受限快照 |
| `POST /api/learning/v1/events/{id}/retry` | 使用 `{ "version": 版本号 }` 重试 |
| MCP `ingest_conversation_event` | 接收事件，保留明确 automation，否则降为 unknown；不允许 Agent 自证人工输入，按用户配置的来源策略处理 |
| MCP `get_conversation_learning_status` | 不返回聊天正文与内部观察，只返回处理／审核状态 |

HTTP 仅限受信任本机，写入需要既有 `X-AI-Persona: 1` 防跨站请求头。它不是远程认证；不要通过反向代理对外开放这些端点。远程 Webhook 的身份绑定、签名、限流、重放保护尚未实现，属于未来适配层。

## 数据、预算与恢复

- 本机队列默认 `~/.local/share/ai-persona/learning/<数据目录路径的摘要>/conversation-learning.sqlite3`，不同 checkout 不共享 Worker。`AI_PERSONA_LEARNING_DIR` 改基础目录，`--queue-dir` 指定精确目录；不要放在 iCloud／网络盘作为跨设备队列。
- 目录权限 0700、数据库 0600；本机当前用户是信任边界，不声称加密或抵御同账号恶意进程。
- 默认无观察正文保留 7 天，观察与恢复上下文 30 天。Worker 运行时定期自动清理，页面无需手动清理。已送审任务的原始正文同样到期清理，候选和备注保留；清理并非磁盘取证级安全擦除。
- 队列保留少量无正文身份／处理信息以去重。观察不进入正常 Persona 检索，批准前不会改变正式 revision。
- 默认每日 50 次逻辑调用、200,000 tokens，按 UTC 日计算；发送前以 UTF-8 大小加输出上限保守预留。模型服务内部重试／已启用备用连接可能产生额外供应商请求和费用，因此不是账单硬上限。
- 学习 Worker 串行调用；Pi 服务原有总并发上限仍为 2。这里不提供对前台请求的严格抢占调度。
- 模型超时、预算暂停、缺少上下文与正常忽略是不同状态。重试复用有效阶段检查点；输入、提示版本、模型路线或 Persona 版本变化使相关缓存失效。
- 送审文件事务已经完成但队列关联未写回时，恢复只补齐关联，不再调用模型；任何已有人工审核决定都不能被新生成覆盖。
