# 对话学习提示词优化与验证方法

本文记录可复用的规则和验证方法，不发布个人反馈正文、模型账号、实验 ID、工作区版本或私人部署结果。当前运行流程见[对话学习使用说明](AI_PERSONA_CONVERSATION_LEARNING_USAGE.zh-CN.md)。

## 优化目标

降低把当前产品规格、临时操作和执行命令误当作长期偏好的概率，同时保留用户明确表达的知识学习与协作要求。信号识别和候选整理分成两阶段，但都必须核对当前请求的对象与意图。

## 两阶段边界

- 可复用的解释、排版、呈现和协作要求可以成为偏好，一次明确纠正即可，不强制要求“以后”或重复次数。
- 当前按钮、字段含义、数值替换、执行命令和一次性例外不自动成为偏好。
- 显式项目协作约定可以形成限定范围的候选，但不能从单次执行指令补出新的政策。
- 知识来自用户当前请求的概念解释、比较或定义更正，不推断掌握程度、兴趣或重要性。
- “解释概念并整理成笔记”不会额外生成“偏好所有内容都写成笔记”；独立的符号定义或版式要求可以另行识别。
- 上下文用于解析当前指代，不使“继续、完成、提交”等操作自动继承历史学习意图。
- 没有合格信号时返回 `ignore`；仅当合理的学习请求缺少必要指代信息时请求补充上下文。

候选整理必须复核信号：误判应丢弃，不通过新建场景、换成知识或转入等待来保留错误信号。有效候选仍需引用已有记录、遵守字段契约、保持范围，不自动批准。

## 合成边界用例

公共测试样本位于 `tests/fixtures/conversation_learning_boundaries.json`，用于覆盖版式、符号定义、图形重叠、知识与偏好混合、项目约定、产品规格、执行指令、一次性例外与指代。

这些样本是开发测试数据，不应冒充用户明确点击反馈形成的个人 benchmark。预期标签不发送给被测模型；用户的不满意理由也不进入评分输入。

## 验证流程

1. 固定提示词、模型、连接修订和测试集版本，记录实际输入预算。
2. 先做离线契约与状态测试，再按需要显式运行模型评测。
3. 将请求被本地校验拒绝、模型调用失败、格式无效、语义不符分别统计。
4. 对混合请求同时检查是否触发、信号类型、数量和候选内容，不能仅看布尔命中。
5. 修改后先定向复测相关边界，再执行约定的完整回归；定向通过不能宣称整个集合通过。
6. 用隔离工作区验证去重、范围、审核与恢复，不向真实待审核区写入评测候选。

小样本、单一模型或只通过离线测试，都不足以证明普遍准确率。比较必须使用相同冻结输入，不以不同轮次或不同配置的结果作无条件 A/B 结论。

## 实现注意事项

评测文档 ID 与模型服务请求 ID 可能遵循不同格式。转换请求 ID 后，取消操作必须使用同一转换结果；测试替身应执行真实适配层的约束，避免模拟测试掩盖接口不兼容。

提示词版本启用与运行快照分开。尚未冻结配置的新任务使用当前版本；已开始任务保留其快照，历史候选不被热更新重写。回退通过提示词版本管理完成，不需要删除模型账号。

外部 Prompt Workbench 可用于提示词编辑与比较，本仓库不包含其应用，见[集成说明](../../../docs/INTEGRATIONS.md)。评测数据的备份与工作区迁移见[数据管理](../../../docs/DATA_MANAGEMENT.md)。
