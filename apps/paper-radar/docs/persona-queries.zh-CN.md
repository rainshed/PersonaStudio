# Persona 查询能力

每日筛选、单篇分析、个性化分析、内容复核和论文讨论共用 AI Persona 的六个只读接口。未选择 Persona 范围的任务不加载这些工具。偏好查询、偏好激活及写入接口均不接入。

| 接口 | Agent 可选择的内容 |
| --- | --- |
| `get_knowledge_map` | 重点节点、关系方向／类型／层数、知识角色、关系重要程度、分页 |
| `search_knowledge` | 查询文字、兴趣、掌握程度、实体类型、材料类型、用户与材料关系、重点节点及关系扩展、分页 |
| `get_persona_records` | 最多 10 个记录 ID、字段投影、原始备注 `body`、是否附带证据、分页 |
| `list_source_files` | 来源、目录、文件类型、递归、分页 |
| `search_source_content` | 多个来源或文件、查询文字、结果数量、上下文长度、分页 |
| `read_source` | 直接通过来源＋文件、证据 ID 或片段读取；目录／文本／图片／结构化视图，页码／行号／区间和续读位置 |

兴趣使用用户记录的 high、medium、low、unspecified；未设置不表示低兴趣。程序不预设兴趣过滤、检索词、研究步骤或阅读顺序。关系探索限定在用户选定范围内。

## 参数与来源

程序固定 `scope` 和 `expected_persona_revision`；Agent 不能通过查询参数扩大范围或切换版本。业务参数全部开放，默认返回 16000 字符，每次可选择 1000–60000 字符。知识与内容搜索最多 50 条，文件列表最多 200 条，单次图片读取最多 4 张。结果包含分页或续读信息。

返回内容保留 Persona 原始字段和来源定位，额外提供 `citation_ref` 作为 Paper Radar 结果中的证据 ID。材料的原始 `source_ref` 继续指向 Persona 来源，可用于列文件。整个查询的 `source_ref` 对应查询条件、版本和覆盖情况，可以区分查询无命中、内容截断和完整列举。选取部分字段不会凭空补入未返回的个人事实。

Codex 接收 MCP 图片内容块；DSH 通过宿主附件服务接收图片。图片字节不混入模型的 JSON 文本，实际可见图片仍取决于所选模型的图片能力。来源哈希和页码随图片保留。

## 筛选、缓存与回放

新建每日筛选只准备所选范围及 Persona 版本，各论文由独立 Agent 按需查询。初始输入包含目标、范围、输出要求和来源，不加载完整知识快照，也不规定执行流程。实际读取的知识、材料与查询覆盖分别记录；检索结果子集不被标记为完整知识扫描。

筛选保存实际 Persona 查询参数和响应，包括图片，以支持固定输入评测。回放使用保存的响应；原始运行未执行的查询返回 `input_unavailable`，不会读取当前 Persona。旧筛选快照继续使用原有分页工具回放。

查询协议版本参与任务缓存身份，旧工具能力生成的结果不会误命中新工具任务的缓存。历史结果、反馈和用户提示词保留。
