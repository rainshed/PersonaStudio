## 真实论文检查与已知问题

使用公开论文 `2412.18602v4`，独立临时数据库，无 Persona 标签，不写入正式论文历史或反馈。

1. 中文 200–400 字：真实模型三次调用成功，但最后正文为 579 个非空白字符；业务质量检查保留候选总结、标记 `needs_review`，任务未报成功。
2. 中文 800–1200 字、明确 low：真实模型三次调用成功，最后正文 1317 字；仍未通过严格字数限制。没有放宽校验，也没有将未合格内容标记成完成。
3. 英文 200–400 词、明确 low：四次真实调用成功，在后续修订／复核前达到 smoke 检查设定的四次调用上限，按预算失败。未把它记为完整分析通过；正式任务继续沿用原有业务预算。

这说明宿主模型接入和显式强度有效，但当前模型仍可能无法遵守 PaperRadar 原有严格字数要求。模型与输入变化需要单独评估；此问题不是认证或通道失败。真实测试详情保存在本机 `.test-output/real-analysis*.json`，该目录不提交到仓库。

最早报告的个性化输入超限另有自动化复现：完整输入超过 300,000 字符时，在调用个性化模型前失败；已完成总结仍可查看，错误为 `context_length`，`retryable=false`，明确说明原样重试不能解决。大输入的自主检索与分层读取仍属于第二阶段。

## 可重复的检查命令

在 `paper-radar/web` 执行：

```sh
npm test
npx tsc --noEmit --pretty false
```

在插件目录执行：

```sh
npm test
node scripts/verify-runtime.mjs "/实际 DSH 安装目录/node_modules"
```

以下检查会产生真实模型用量，只用于有意进行的连接／业务检查，不应作为普通测试自动重复运行：

```sh
node scripts/verify-runtime.mjs "/实际 DSH 安装目录/node_modules" --model-call
node --experimental-strip-types scripts/verify-analysis.mjs --run
node --experimental-strip-types scripts/verify-discussion.mjs --run
```

真实总结脚本限制最多四次调用、六分钟执行时间；讨论脚本限制三分钟。均不读取 Persona，测试数据独立于正式数据库；运行结果不合格时退出失败并保留检查结果。
