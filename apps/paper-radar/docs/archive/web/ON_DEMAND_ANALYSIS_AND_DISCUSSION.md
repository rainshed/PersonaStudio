# 推荐严格度、按需分析与论文讨论（v0.4）

实现日期：2026-09-07。适用于本机 Node 服务和真实 Web UI；静态演示不调用这些后端。本文覆盖旧 D1 文档中自动全文分析、日报完成条件及父子任务预算关系。

## 使用流程

1. 在“我的订阅”编辑推荐严格程度：聚焦、均衡（默认）、探索。每篇独立判断相关性，不设每日配额或比例，零篇和多篇都有效。修改用于新的运行；对已有公告使用“按当前订阅重新筛选本批”，保留旧版。
2. 生成日报后先看文章介绍与推荐理由。来源完整、所有候选初筛成功即完成日报；需要更多证据的论文留在“待确认 / 未完成”，不因不确定而自动启动全文分析。
3. 对任何未排除的候选点击“详细分析”。这会明确创建独立的单篇任务；在详情或单篇任务中查看、取消、重试。完整报告可显式重新生成，旧报告与评价保留。
4. 点击卡片上的“讨论”或单篇入口的“先讨论这篇论文”。无需先生成报告。打开窗口只读取会话；发送问题后才读取必要证据并调用模型。
5. 报告的六节总结、推荐理由、材料联系及交叉问题各有讨论按钮，也可选中文字后点击“讨论选中文字”。问题和前提显示在讨论顶部，可以编辑问题再发送。再次打开同一问题继续已有会话；下拉菜单切换主题，“新会话”创建独立上下文。
6. 中文模式使用中文解释，保留 English 专业术语、方法名、符号和缩写。它是初筛、总结、联系和讨论共用的生成规则。已有旧结果不自动改写。

桌面使用较宽的讨论窗口，手机使用全屏讨论界面。消息保存于本机 SQLite；关闭窗口不会取消任务。当前按轮返回完整回答并轮询进度，不提供 token 流式输出。消息中的公式目前保留模型输出的文本/LaTeX 表达，不承诺数学排版渲染。

## 状态与预算

- **初筛**：`screening.v3-knowledge`，必含 `introduction`、`reason`、`outcome`、证据和可核验个人事实。`recommended / not_recommended / needs_fulltext` 与筛选失败分开。`stats.screened` 表示完成初筛数量，`stats.screening_pending` 表示尚未成功初筛，`stats.needs_confirmation` 表示已有证据但仍待确认的判断。
- **报告**：`details_status` 独立保存 `not_requested / queued / running / available / partial / failed / cancelled / interrupted`。详细分析保留初筛列表归属及理由，全文意见保存为独立 `analysis_decision`。全文不推荐、不确定或失败都不会移走推荐项，也不使已完成日报退回未完成。
- **预算**：日报上限只覆盖初筛及其平台/格式重试。手动报告沿用每篇最多 12 次模型尝试与 15 分钟执行边界；模型设置在点击时固定，标签、语言、字数及严格度沿用所选日报版本。报告不会因日报预算用完而被阻止。
- **取消**：取消日报停止初筛，不取消已经明确请求的报告。取消全文通过对应 `/jobs/:id/cancel`。删除日报前会停止其独占任务。
- **讨论**：新增 `discussion` 模型路由，默认继承现有默认模型，可单独选择连接。每轮固定模型设置，最多 4 次实际尝试、5 分钟；结构/引用错误最多修正一次。显式重试增加一个有界尝试窗口。每个会话同一时间只有一轮回答，讨论服务串行消费持久化队列，与其他任务共享模型并发上限。
- 已到达平台的调用无法在本地回滚；重启可能导致某轮重新调用。记录实际尝试和平台返回的用量，不保证外部模型恰好执行一次。

## 上下文与证据

自由讨论在首轮发送后读取指定论文版本和固定标签内材料，保存本会话快照。从报告发起时固定报告 ID、论文版本、章节/问题原文及报告证据；若原报告尚未取得 Persona 材料，首轮会在相同标签范围补取快照；重新生成报告不会改写旧会话。客户端提交章节类型和索引；服务端解析原报告，选中文字必须是报告中的真实子串。讨论不把报告设想当作科学事实，提示模型检查前提、原文是否已经回答、证据边界与待验证问题。

正文较短时使用全部已有证据；长正文按当前问题、锚点引用及最近三轮回答的引用选择片段，界面明确显示片段数和未覆盖全文的事实。此阶段是有界文本相关性选择，并非向量检索或完整长文推理系统。会话历史不静默截断；历史或整体输入超过边界时要求开启新会话或更大上下文模型。不会触发六节全文报告流水线。

每轮保存实际提供的证据，模型返回的证据 ID 必须属于本轮；引用查看同时检查会话 ID、消息 ID 和证据 ID。涉及兴趣、知识程度、偏好、作者关系的结构化 claim 必须匹配原始 Persona 字段。没有检索全部文献时不能声称全领域新颖。结构和引用校验不能保证科学结论正确，推理质量交给所选模型，不添加针对小模型的领域补丁。

四项反馈仍全部可选。初筛只提供准确性与理由反馈；全文反馈按已生成内容开放。阅读、聊天、关闭报告和无反馈均不产生评价、不自动调整严格度、不写回 AI Persona。

## 存储与接口

SQLite 的 **v3** 迁移增加 `daily_detail_requests`、`discussions`、`discussion_turns`、`discussion_requests`。新表与论文/报告建立引用关系。旧 D1 中尚未执行的自动全文任务被取消；已完成报告、初筛证据和反馈保留，旧初筛没有介绍时明确显示原始摘要。旧模型设置新增 `discussion: null`，继续使用原默认连接。

后续 **v4** 迁移恢复旧日报的初筛列表归属，独立保存原全文意见，保留全部报告及反馈；不调用模型。初筛反馈与全文内容反馈分别绑定各自版本。

数据库、会话和证据位于 `~/.local/share/paper-radar/data/`；密钥继续留在独立的模型凭据目录。使用 AI Persona 的六个新版查询工具，统一执行完整知识点、scope/revision 和来源校验，详见[新版 Persona 对接](AI_PERSONA_QUERY_V2.zh-CN.md)。讨论可按问题补充当前固定版本的原文；版本变化时只使用已有证据并提示限制。没有修改 localhost 监听、同源 API、Host/Origin 校验或 Tailscale 转发规则。

| 接口 | 行为 |
| --- | --- |
| `PATCH /api/subscriptions/:id` | `recommendation_strictness`: `focused / balanced / exploratory`，沿用 revision 冲突检查 |
| `POST /api/daily-items/:id/analyze` | 明确请求全文，`{force_regenerate?: boolean}`；返回 `job/item/run/reused`，需幂等键 |
| `POST /api/discussions` | 来源为 `daily_item_id`、`analysis_id` 或 `input`；可提供 `anchor`、`new_conversation`，创建或恢复，不调用模型 |
| `GET /api/discussions/:id` | 本会话、消息、来源和同一上下文的相关主题；不返回内部提示词和原始私有上下文 |
| `POST /api/discussions/:id/messages` | `{question}`，创建持久化异步消息，需幂等键 |
| `POST /api/discussion-messages/:id/cancel` | 取消当前轮次并阻止迟到答案覆盖 |
| `POST /api/discussion-messages/:id/retry` | 重试会话末尾失败/取消/中断消息，需幂等键 |
| `GET /api/discussions/:id/messages/:turnId/evidence/:evidenceId` | 本轮原始证据 |
| `DELETE /api/discussions/:id` | 停止本会话任务，删除消息和上下文，保留论文及报告 |

写请求沿用 JSON + `X-Paper-Radar: 1`；需幂等键的请求使用 `Idempotency-Key`。同键不同参数返回 409。报告/日报仍被讨论引用时先返回 409 并提示删除相关讨论，避免失去会话的报告来源。
