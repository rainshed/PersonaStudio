# Paper Radar 对接 AI Persona 新查询接口

更新日期：2026-09-09。本次重构用于本机真实服务；线上静态演示不连接个人知识库。

## 保留的推荐逻辑

```text
arXiv 分类 → 论文候选池
用户选择的 Persona tags（并集）→ 这些标签下的全部知识点 → 逐篇推荐判断
                                                ↓
                                   同一范围内的关系与材料辅助解释
```

标签是用户选择推荐知识范围的入口。初筛不按每篇论文关键词裁剪知识点，不用材料清单替代知识点，也不根据知识库没有某内容推断用户不感兴趣。聚焦、均衡、探索仅改变关联强度要求，不改变标签边界。

知识点以完整记录提供给模型，保留 `scope_note`、`knowledge_level`、`interest_level`、`body`、记录版本及 provenance；`unspecified` 不转换为低兴趣或不熟悉。每个初筛判断和全文推荐判断都必须引用所选知识点。服务端从有效引用计算 `matched_knowledge_ids`，页面以“判断依据的知识点”展示；该字段也适用于解释不推荐的判断，不代表一定存在正向关联。

## 六个接口与统一读取层

`server/persona/query-client.mjs` 只接受 `ai-persona.query-result/v2`，检查工具能力、响应结构、scope 和 Persona revision。`server/persona/service.mjs` 为日报、单篇分析和讨论提供统一业务上下文。

| 接口 | Paper Radar 的用途 |
| --- | --- |
| `get_knowledge_map` | 读取标签目录、固定当前范围和版本、展开相关知识邻域 |
| `search_knowledge` | 空查询配合 `entity_types: [knowledge_node]` 分页列出完整推荐知识点；非空查询查找辅助材料 |
| `get_persona_records` | 每批最多 10 条，读取完整字段、备注及证据来源；重组分页长字段 |
| `list_source_files` | 查看已知材料的可读来源文件 |
| `search_source_content` | 在同一标签范围内，定位与论文或当前问题相关的原文片段 |
| `read_source` | 通过不透明 passage 引用读原文，保存文件哈希、行号或页码、定位范围 |

不保留旧 MCP API、旧响应包裹或直接读取材料磁盘路径的兼容实现。启动连接只检查六个新工具；不调用激活、偏好匹配或写入工具。

仅标签选择页允许无 scope 的目录发现，响应中的图节点不保存、不返回前端、不发送给模型。业务读取始终传入非空标签 scope，后续请求携带同一个 `expected_persona_revision`。多标签固定 `tag_match: any`。

搜索结果的 `hits` 定义知识点目录；`nodes` 中的邻接材料不成为推荐知识点。补充材料必须能沿返回的关系图连接到所选知识点。文本、语义和图检索的命中原因作为检索信息保存，不变成个人兴趣或能力事实。直接引用关系仍需核对论文参考文献的标识符或唯一完整标题。

## 完整性与版本

初筛必须取得全部选定知识点及其完整记录。分页遗漏、游标循环、记录缺失、越界返回或总数不一致都会阻止推荐；知识点为空时明确提示，材料不能作为替代。长字段续读按 Python 的 Unicode 字符计数重组，避免中文和 emoji 备注错位。

当前单次知识目录最多 1000 个知识点，记录/上下文采用 400 KB 上限；超限明确要求缩小范围，不静默删减知识点。补充检索采用有界候选与两跳关系图，每次最多增加 24 条辅助记录。材料原文最多访问 8 个来源、每个来源最多 4 个文本文件；每个片段最多读取 9000 字符，上下文原文累计最多 45000 字符。辅助检索未遍历的分页、语义检索降级、不可读文件及原文片段未读完都会作为覆盖限制保存。

AI Persona 的 revision 用于校验当前内容，**不是历史版本读取参数**。新分析遇到版本、来源或游标变化时，最多重新读取整套依据一次。保存结果包含实际使用的知识点、关系、证据原文、检索覆盖和出处，无需上游提供历史回放。

讨论按当前问题补读，但只能补充到该会话已固定的 Persona revision。版本变化时继续使用已保存证据并说明限制；若要使用最新依据，应重新分析后发起讨论，或从指定论文输入另开讨论。每轮证据单独保存，后续问题不会改变以前回答的引用。讨论的证据预算优先保留完整知识点，超限时明确报错。

## 升级行为

- 新上下文：`paper-radar.persona-context/v2`；初筛：`screening.v3-knowledge`；全文：`single-v3-knowledge`；讨论：`discussion.v2-persona`。
- 连接配置和稳定连接身份保持不变，现有订阅的标签选择无需重新填写。
- 旧结果、原始依据、讨论和反馈保持可读；旧流程缓存不参与新流程的结果复用。
- 尚未完成的旧初筛任务提示“按当前订阅重新筛选本批”；旧单篇任务可通过重试创建新版任务。旧报告发起的讨论使用原先保存的依据，不尝试调用旧接口。
- 无标签的单篇研究总结不读取 Persona。日常自动检查仍由公告变化触发；更新代码或 Persona 不会自行重跑历史论文。
- 新默认提示词描述知识点优先及来源限制。已启用的自定义提示词保留，服务端仍强制执行完整知识点、范围、版本与引用校验。

真实集成测试启动相邻 AI Persona 项目的 Python MCP 服务，使用临时复制的 demo 数据和禁用语义模型的检索器，实际调用六个查询接口。不读取个人知识库、不调用付费模型。默认使用 `../../../ai-persona/.venv/bin/python`（相对于测试文件）；也可设置 `AI_PERSONA_TEST_PYTHON`。缺少解释器时该集成项明确跳过，其余测试仍运行。

本次验证证明接口、状态和数据约束可运行，不替代使用真实模型评估推荐质量。
