# 每日推荐：实现与运行（v0.4）

更新日期：2026-09-08。新增能力与接口详见[按需分析与讨论](ON_DEMAND_ANALYSIS_AND_DISCUSSION.md)和[自动日报](AUTOMATIC_DAILY.zh-CN.md)。当前支持本机单用户、手动和定时生成真实日报，以及按公告日期使用已存档或官方当前 feed 中的批次生成日报。自动路径先比较实际来源内容，没有更新不创建任务或调用模型。作者身份匹配、外部通知和任意历史公告补抓尚未实现。

## 开始使用

在 `web/` 运行 `npm run build`，然后运行 `npm run start:local`，打开 <http://127.0.0.1:4317/>。不需要保持浏览器或 Codex 对话打开，任务由本机服务继续执行；电脑休眠或服务停止会中断执行。

1. 在“模型设置”配置已授权的连接。初筛使用 `screen`，研究总结使用 `summary`，个性化分析使用 `connections`，论文讨论使用 `discussion`，没有覆盖时继承默认连接。
2. 在“我的订阅”或每日论文页新建订阅：一个或多个 arXiv subject、实际 Persona 标签、推荐严格度、中文或英文、按需总结字数范围，以及初筛请求上限。分类可以搜索、多选或逐个移除，至少保留一个。
3. 点击“生成最新一批”。服务保存本批次来源和设置，然后筛选全部纳入候选。

也可以在“公告日期”日历选择日期，再点击“生成所选日期日报”。圆点表示已有日报，下划线表示当前订阅的全部分类都有完整公告存档。未来日期不可选。所选日期保留在 URL 和任务中，刷新页面或生成失败后仍能知道正在处理哪一天；“返回最新”恢复最新公告模式。

按日期生成优先使用该日完整存档；缺失或不完整时检查官方当前 feed 并只选择日期严格匹配的公告组。同一天重复生成可重用已有结果，不自动重跑模型；不同日期的请求独立。多分类中有部分来源缺失时保留该日可核验论文并标注覆盖缺口，全部来源缺失时明确失败、不创建空日报。无公告日、尚未发布、历史未存档和抓取失败不能被当成“当天没有论文”。
4. 查看推荐、未推荐、初筛未完成、关联待确认及版本动态。先展示介绍与理由；主动点击详细分析后生成总结、联系与交叉，也可以直接讨论论文或报告问题。
5. 失败、中断或预算暂停时点击“继续未完成部分”；使用新设置重新分析，选择“按当前订阅重新筛选本批”。

真实页面由 `/api/capabilities.daily_recommendation` 选择。已知静态演示地址和独立开发预览保留虚构示例；真实入口连接失败会报错，不能自动换成演示成功结果。

前后端继续使用同源 `/api/`。没有修改监听地址、Host/Origin 约束或 Tailscale 配置，手机实际转发链路仍须在手机上确认。

## 订阅与数据范围

- 提供从 arXiv 官方分类目录取得的 155 个 subject；目录快照记录来源和更新日期，存于 `server/daily/subjects.json`。
- 支持多个独立订阅，每个订阅一个或多个 subject。分类取并集，跨分类重复论文只筛选一次，论文卡片标注命中的分类。标签使用稳定 ID，多选按并集处理。
- 启用和生成个性化日报需要非空有效标签；空标签可保存草稿。无标签的纯总结继续在单篇入口使用。
- 标签名称从 AI Persona 实际读取。标签失效、连接变化、分页不完整或没有范围内知识点时明确失败，不回退至全库。
- 每个订阅独立保存语言、总结长度和请求上限。当前总结范围沿用单篇：200–3000，默认 800–1200；中文按非空白正文字符，英文按单词。
- 默认筛选新作与新跨分类，更新和更新后跨分类单列。可以显式开启更新版本筛选。
- 草稿、停用和归档状态不能创建新的日报。归档保留历史；已经创建的任务使用自己的不可变设置，不随订阅编辑改变。

初筛在同一 scope/revision 下完整读取所选标签下的全部知识点，每个候选使用同一快照，最多 1000 个；超过上限明确提示缩小范围。知识点范围说明、掌握程度、兴趣程度、备注和出处均保留。材料不能代替推荐知识点，也不会用论文关键词命中子集替代完整知识范围。模型判断必须引用所选知识点；全文阶段使用相同读取层并按需补充关系与原文。详见[新版 Persona 对接](AI_PERSONA_QUERY_V2.zh-CN.md)。

初筛与全文阶段分别保存实际 Persona revision；全文阶段可能取得更新后的证据。整份日报不假定所有阶段使用同一历史 revision，也不会把旧初筛理由拼成新全文结果的证据。

## 公告来源与完整性

读取官方 `https://rss.arxiv.org/atom/<subject>`。公告条目的 `published` 用于公告日期，`id` 用于固定版本，`arxiv:announce_type` 用于类型。`updated` 只是 feed 生成时间；不使用过去 24 小时的提交日期替代本次公告。

保存原始公开 feed、来源哈希、解析版本、归一化批次及不可变修订。仅改变 feed 生成时间或条目顺序不会触发新分析。同一订阅内按基础 arXiv ID 合并重复，版本或内容冲突显示来源不完整。不同订阅的个性化判断分别保存。

完整性表示：读取了完整闭合的官方 subject ATOM 响应，所有条目可解释、低于可能的容量上限且无未解决冲突。先用 [saxes](https://github.com/lddubeau/saxes) 检查 XML 结构，再提取字段；不能依赖宽松解析器自动补齐缺失标签。当前 feed 不提供独立总数，覆盖限于本次公开来源；界面保留这一说明。截断、未知条目、版本冲突及达到容量阈值均不标为完整。

空 feed 缺少可核验公告归属时，显示日期无法确定，不能说“今天没有论文”。如果来源明确、但条目全部是订阅未纳入的更新，则可以完成一份候选数为零的日报，且不调用模型。

相同 subject 的并发请求共用来源获取及短时缓存，单篇与日报使用同一 arXiv 下载器和串行限流。已归档批次可以精确重放，也可以按公告日期选择生成。官方 RSS/ATOM 没有历史日期查询参数；本阶段不提供任意历史日期的自动补抓，也不把 API 的 submittedDate 提交日期替代公告日期。参考：[官方 feed 路由](https://github.com/arXiv/arxiv-feed/blob/develop/feed/routes.py)、[API 日期查询说明](https://info.arxiv.org/help/api/user-manual.html)。

`POST /api/daily-runs` 新增 `source: {"kind":"announcement_date","date":"YYYY-MM-DD"}`。日期必须有效且不晚于当前 UTC 日期。原有 `latest_announcement` 和固定 `stored_batch` 保持兼容。`GET /api/daily-reports?subscription_id=...` 增加 `available_dates`，列出当前订阅全部分类都有完整公告存档的日期；它与已经生成日报的 `dates` 分开，且不受当前查看日期过滤。

多分类订阅分别抓取各个分类，每组最多三个并发来源，并保存各自来源修订及合并修订。以最新成功来源的公告日期为本批日期，其他日期的旧论文不混入；失败、日期不同和元数据冲突分别显示覆盖缺口，整批保留为部分完成。全部分类失败则明确报错，不创建空日报。来源恢复后点击“生成最新一批”重新收集；“继续未完成部分”只继续已有不可变批次中的筛选。

同篇同版本在任一分类属于新作或新跨分类，即纳入默认筛选；均为更新的论文继续按更新开关处理。同篇出现不同版本时保留最高版本，标记来源冲突，并保留各分类原始版本信息。跨分类去重在初筛前进行，共用同一个订阅范围内的判断。

修改订阅分类后，历史日报仍显示原有分类集合；不同范围的旧批次不允许按新范围重筛，页面引导重新“生成最新一批”。

## 筛选与详细分析

每个候选先用标题、摘要、分类、明确版本和限定 Persona 证据做初筛。输出 `recommended / not_recommended / needs_fulltext`，使用与校验器一致的完整 JSON Schema 描述协议，校验论文 ID、JSON 结构、引用存在性与个人事实。格式失败最多再生成一次，保存有限的协议错误记录；平台瞬时失败沿用已有有界重试。

初筛推荐、未推荐和待全文确认均可结束该篇初筛，不自动创建全文任务。按聚焦、均衡或探索的相关性规则独立判断，没有固定篇数或比例，也不将模型失败归入未推荐。每篇初筛提供独立的文章介绍和推荐理由，中文叙述保留 English 专业术语。

详细分析仅由用户明确触发，固定点击时的模型配置，并沿用对应日报的标签、语言、字数和严格度。它独立进入现有单篇队列，使用每篇自己的执行与请求预算，不重新开启日报初筛。

用户请求详细分析表示希望进一步了解论文。列表归属始终保留初筛结果，全文不推荐、判断不确定或分析失败都不会把已推荐论文移走。全文模型意见通过 `analysis_decision` 独立保存并展示为“全文补充意见”，卡片继续显示原初筛理由。始终满足：

```text
筛选候选数 = 初筛推荐数 + 初筛未推荐数 + 初筛待确认或未完成数
```

来源完整且全部候选完成有效初筛时，日报标记完成；其中可有待进一步确认的关联。是否请求全文、全文是否成功都不影响初筛完成状态。来源缺口或初筛失败保留为部分完成。

未推荐论文也可以主动追加全文分析，仍保留原列表归属。全文意见建立新版本，旧初筛与旧反馈保留。缺少可靠材料联系或交叉时允许空结果。

## 任务、预算与恢复

- 创建运行立即返回持久化任务；没有抓到来源的失败任务也出现在历史中。
- 同一幂等键的重复请求复用任务；同键不同参数返回 409。相同来源和设置再次生成也复用已有日报，不重复消耗模型额度。
- 订阅 + 公告批次构成逻辑日报；强制生成或使用新设置产生新运行版本。
- 浏览器只保存表单或当前选择等界面状态，真实订阅、来源、任务、结果和反馈保存在后端。
- 日报预算按初筛实际模型尝试计数，包括格式重试和平台重试。手动详细报告和讨论独立计量。达到后暂停，可增加累计上限继续；剩余候选不丢弃。
- 取消日报停止初筛，保留已完成内容，不取消用户已明确发起的详细任务；详细任务单独取消。
- 运行中重启后显示中断，可手动继续；已完成初筛和兼容的单篇组件复用，关联任务可以恢复。
- 取消尚未结束时不能立即重启同一运行，以避免迟到结果覆盖恢复任务。
- 单篇历史中的日报子任务通过“重试详细分析”恢复，仍归属于原论文，使用独立任务预算。

调用已到达平台但响应尚未持久化时发生中断，后续可能需要重新请求。请求数记录已开始的尝试，用量只汇总已收到的数据；不承诺外部模型严格只调用一次。平台未提供费用时显示“费用未提供”。

## 可选反馈与删除

反馈仍只有准确性、总结、理由、联系与交叉四项，没有阅读状态或行为学习。

初筛版本只接受准确性与理由反馈；全文结果按对应组件是否有效开放反馈。负反馈理由可空，未填写不写记录。反馈可修改或撤销，内容重新生成后不复制旧评价。

卡片及详情中的初筛准确性、初筛理由反馈始终绑定筛选版本，生成报告后不会换到全文版本。报告中的总结、全文意见及材料联系反馈沿用原分析结果的记录，因此日报和单篇历史不会产生两份报告评价。来源详情和用户反馈分别保存，不以程序验收意见代填用户反馈。

删除日报会清理其所有运行版本、初筛反馈、独占个人快照及由它创建且未被其他日报引用的分析。公共论文来源缓存保留。单篇结果仍被日报引用时会阻止独立删除；日报或报告被讨论引用时需先删除相关会话，避免悬空引用。

## 存储与接口

数据库仍为 `~/.local/share/paper-radar/data/radar.sqlite`，依次从 v1/v2/v3 事务迁移到 v4，保留已有单篇历史、报告与反馈。模型凭据继续保存在独立加密目录。运行数据与凭据均在源码和云盘项目之外，不进入静态部署包。

新增表管理订阅、公开公告快照与修订、日报及候选版本、模型尝试和筛选反馈。个人快照受本机数据目录权限保护；业务数据库不是加密数据库。

主要接口：

| 路径 | 用途 |
| --- | --- |
| `GET /api/arxiv/subjects` | 官方分类目录快照 |
| `GET/POST /api/subscriptions` | 订阅列表与创建 |
| `GET/PATCH /api/subscriptions/:id` | 读取和按 revision 修改订阅 |
| `GET/POST /api/daily-runs` | 任务历史与手动生成 |
| `GET /api/daily-runs/:id` | 进度、来源、范围与用量 |
| `POST /api/daily-runs/:id/cancel`、`/retry` | 取消、恢复及增加累计请求预算 |
| `GET /api/daily-runs/:id/items` | 分类、状态、搜索和分页 |
| `GET /api/daily-reports`、`/:id` | 按订阅/公告日期查询日报及版本 |
| `DELETE /api/daily-reports/:id` | 删除日报 |
| `GET /api/daily-items/:id`、`POST /api/daily-items/:id/analyze` | 详情与主动全文分析 |
| `GET /api/daily-item-versions/:id/evidence/:evidenceId` | 对应判断的受控证据 |
| `PUT/DELETE /api/daily-item-versions/:id/feedback/:dimension` | 对应内容版本的反馈 |

写请求沿用 JSON 和 `X-Paper-Radar: 1`。生成、恢复和主动全文分析需 `Idempotency-Key`。模型、Persona 和单篇接口保持兼容。

订阅创建/修改使用 `subjects: ["cond-mat.stat-mech", "quant-ph"]`，传入时完整替换分类集合，后端验证官方分类并去重排序。保留旧 `subject` 请求兼容：只传单值相当于单分类集合。新存储保留首个分类的 `subject` 兼容字段；旧存储没有 `subjects` 时按单分类读取，历史快照不重写，不需要额外 SQL 迁移。日报及来源信息包含完整 `subjects`；合并来源的 `sources` 保存各分类状态，论文的 `matched_subjects` 与 `source_matches` 保存命中及版本来源。
