# Paper Radar 架构

`web/` 是完整应用。网页、本机 HTTP 服务和业务数据生命周期一起开发，无须拆为两个部署项目。

| 模块 | 职责 |
| --- | --- |
| `analyses`、`daily` | 单篇论文、日报订阅与调度、按姓名和 subject 匹配关注作者论文 |
| `evaluations`、`prompts` | 显式反馈与评测、提示词版本与试跑 |
| `persona` | 用户指定知识范围内的查询与来源读取 |
| `storage` | 数据库与迁移 |
| `notifications`、`tasks` | 业务通知、排队、取消与恢复 |
| `agents` | 两种宿主共用的研究工具、证据账本、结构化提交和结果校验 |
| `hosts` | 宿主选择、冻结配置、连接、认证、传输、取消和计量 |
| `integrations/dsh` | 将 DSH 对话操作转换为本应用的查询与业务动作 |
| `plugins/dsh` | 必须加载进 DSH 进程的工具注册、宿主能力调用及卡片 |
| `packages/host-contract` | 通信标识、能力描述、输入格式和结果结构 |

宿主执行过程中的工具回调属于 `hosts`，即使请求方向是从宿主进入应用。
DSH 对话直接发起业务操作才属于 `integrations/dsh`。
Codex 使用 App Server 和任务范围内的工具桥接，无需额外 Codex 插件。

业务任务优先级与生命周期由 `tasks` 管理，实际宿主调用额度由适配器控制。
冻结任务使用自己的宿主标记；改变默认宿主只影响新任务。
新增 Agent 宿主时应实现同一调用能力和设置接口，再接入宿主入口，不在业务模块中增加供应商客户端。

共享协议包不导入 Node 网络、文件系统、宿主 SDK 或应用源码。传输实现在两个进程各自的模块中，模型选择优先级在 DSH 插件内部实现。协议格式校验可以共享，业务任务执行不能进入协议包。

前后端共享的输入、状态定义位于 `web/lib/contracts/`，路由偏好位于 `host-settings.ts`，不含认证信息的宿主模型快照位于 `host-models.ts`。其余 `lib/` 文件也可以是客户端请求与界面辅助函数，不意味着全部在两端共用。

独立模型的供应商 SDK、账号/凭据库、连接编辑页、HTTP 账号管理接口和旧固定分析流水线已移除。历史快照的识别仅用于拒绝重放，不提供旧模型执行方式。提示词工作台的单次文本试跑也必须通过当前 Agent 宿主完成。

论文讨论功能已下线。`discussions` 保留历史数据结构与兼容代码，生产服务不创建讨论服务、不挂载讨论 HTTP 接口，DSH 不暴露讨论操作。删除原报告时仅解除历史讨论的外键关联，保留已保存的内容。

## 关注作者

`subscriptions.data.followed_authors` 保存每个订阅的完整作者姓名列表，旧订阅缺省为空。`lib/author-following.ts` 统一执行完整姓名匹配（忽略大小写、多余空格，统一 Unicode 组合形式）和 subject 交集检查，不做缩写展开或身份消歧。

`PUT /api/subscriptions/:id/followed-authors` 通过订阅修订号防止覆盖并发修改，不依赖 Persona 或模型。`GET /api/subscriptions/:id/author-papers` 从分类公告存档中匹配、去重和分页；同一路径的 `POST` 先调用已有分类来源读取器，再返回匹配结果与各分类来源状态。读取失败保留旧存档并报告失败，不能把失败当作没有论文。

关注名单与当前 subject 是浏览过滤条件，不改变冻结的日报判断。作者列表及日报的 `followed_authors` 页签使用当前订阅设置，包含未推荐或尚未初筛的匹配论文。单独的作者列表不要求先生成日报；既有自动来源检查归档的论文也能直接匹配。
