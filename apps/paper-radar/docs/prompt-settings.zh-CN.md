# 提示词设置与模型输入

在“设置 → 提示词”先选择生成语言，再选择共用规则或任务。中文、英文分别保存；切换语言、任务或筛选规则会保留当前页面中的草稿。刷新或离开应用前请保存。设置页的语言选择只决定编辑对象，不改变订阅或分析的生成语言。

## 共用规则与每日筛选

- **共用规则**：自动应用于所选生成语言的当前全部任务。中文以原 `terminology` 内容为初始规则，英文初始为空。两者都可以自由编辑或留空。
- **任务提示词**：各任务、各语言分别保存具体目标、分析重点和内容要求。原先藏在 `taskGoal()` 中的业务目标已迁入可编辑模板。任务输入模板保留在折叠的高级选项中，`{{task}}` 自动填入本次问题、参数、资料引用和输出结构。
- **每日筛选**：选择聚焦、平衡或探索后，编辑对应提示词；“每日通用要求”用于该语言的所有每日筛选。真实执行使用订阅中保存的规则，编辑页面切换选项不会改变订阅。
- **提示词与输入**：编辑要求的同时，查看自动加入的任务参数、论文资料、个人知识范围、已有内容入口、输出结构、工具定义和运行环境补充。每部分标明来源、加入条件、阶段、是否加入及是否可编辑。修改资料与任务参数的入口也会说明。
- **发送预览**：使用当前相关草稿，默认搭配示例资料；显式载入真实运行记录后，也可以使用其中的资料重新组合。旧记录未保存工具定义时，重新组合使用当前工具与输出协议，历史记录本身仍标注不完整。重新组合与历史输入明确区分。切换预览运行环境或示例知识范围不会改变真实任务设置；预览不会调用模型或读取工具。
- **运行记录**：查看某次执行当时保存的初始请求、提示词版本、工具调用、返回内容、校验反馈、备用模型重启、运行环境接收确认与条件性追加消息。旧记录仅有初始提示词，会明确标注当时未记录的部分。
- **保存当前组合并启用**：一次保存当前任务涉及的任务模板、共用规则和所选筛选规则的修改。页面列出保存内容，并提示共用规则影响同语言全部任务；其他未相关草稿保留。“恢复此项默认”和“载入历史版本”只载入草稿。

每日筛选只组合：当前语言共用规则（非空时）＋当前语言每日通用要求＋本次所选规则＋本次任务资料。其他筛选规则不出现在发给模型的输入或实际使用版本列表中。其余任务只组合当前语言共用规则、该任务提示词和任务资料。共用规则自动加入，无需维护 `{{@...}}` 引用。

## 当前使用的提示词

下表中的 `{lang}` 为 `zh` 或 `en`。

| 用途 | 实际版本 ID |
| --- | --- |
| 共用规则 | `paper-radar.shared.{lang}` |
| 每日筛选通用要求 | `paper-radar.screen-autonomous.{lang}` |
| 聚焦、平衡、探索 | `paper-radar.screen-focused.{lang}`、`paper-radar.screen-balanced.{lang}`、`paper-radar.screen-exploratory.{lang}` |
| 单篇完整分析 | `paper-radar.task-single.{lang}` |
| 独立研究总结 | `paper-radar.task-summary.{lang}` |
| 独立个性化分析 | `paper-radar.task-connections.{lang}` |
| 按需内容复核 | `paper-radar.task-review.{lang}` |

生产入口继续使用不带语言后缀的任务 ID，组装时根据任务冻结的生成语言、筛选规则选择具体版本。定义见 `web/server/prompts/language-prompts.mjs`，语言选择策略见 `render-policy.mjs`。

系统指令使用带 `kind`、`source`、`text` 的结构化列表，来源包括提示词 ID、版本、语言和所选规则。论文、个人知识、问题、工具及输出接口由任务另行提供；用户编辑规则不改变工具协议。

工具定义在任务开始时提供，正文、知识原文等通常在工具调用后追加；“可读取”不等于“已经发送”。完整原始视图保留实际消息角色、正文、工具定义和运行环境的完成回执结构。Codex 的基础指令、MCP 工具说明及回执结构与执行适配层共用定义；DSH 未提交结果时的提醒也由共用函数生成。

总结的六节结构、必填字段和引用有效性仍由程序校验，页面只读展示；不能仅靠修改提示词覆盖。语言、长度和知识范围在现有任务设置中配置。本次没有开放任意修改输出协议或工具权限。

AI Persona 仍提供所选范围内的知识记录、材料和来源证据。此变更没有增加长期行为或写作偏好的自动加载。

## 迁移、历史与缓存

- 继续使用现有 `prompts.sqlite3`。首次升级以事务、逐项标记的方式迁移已有兼容版本和启用选择；重复启动不会覆盖新修改。
- 原术语规则迁入中文共用规则；原任务提示词与三种严格度提示词迁入各自语言版本。原任务中的共用规则引用由系统组装替代，其余自定义内容保留。原始版本保留在工作台和历史数据中。
- `defaultCatalog()` 为设置页提供按语言标记的条目，默认内容来自服务端，客户端不复制默认提示词。
- `/api/prompt-settings` 提供目录、详情、预览、保存启用、恢复版本、`save-batch` 批量保存和 `runs` 运行输入记录。预览草稿限定为当前语言、当前任务和当前筛选规则；真实资料须显式选择对应任务与语言的记录。所有接口沿用应用来源校验，不提供模型调用。
- 保存校验字段、变量、长度及受影响的组合；使用 `expected_active` 检查并发冲突。冲突时保留草稿，读取最新启用版本后比较再保存。
- 任务创建时冻结提示词快照，执行使用任务中冻结的语言与筛选规则。运行中的任务及原任务重试保持原版本；升级前的快照继续使用旧组装策略。
- 新快照增加 `context_policy: editable-task-instructions/v1`。首次升级将业务目标加入当前语言任务模板并保留自定义正文及原版本；迁移只执行一次。没有这一标记的旧任务仍使用原动态目标构造方式，保证重试兼容。
- 缓存指纹只纳入当前任务实际选用的语言和筛选规则。修改另一种语言、其他任务或未选用的筛选规则，不会无故重跑当前任务。

## 组装与记录的实现边界

- `agents/task-input.mjs`：自主任务的实际输入、结果结构和工具组合；设置预览复用相同构造函数。筛选预览复用 `ScreeningEvidence.initial()` 和 `toolset()`，示例不执行网络读取。
- `prompts/agent-context.mjs`：根据实际请求生成供 UI 展示的来源清单，记录 Agent 启动输入与工具交互。展示用的标题、状态、修改入口不作为额外提示词发送给模型。
- `packages/host-contract/context.mjs`：运行环境固定指令、条件性提醒和接口定义的唯一来源。模型路由及服务内部上下文仍由运行环境控制。
- 新运行输入与追加事件保存在提示词数据库的 `context_runs`、`context_events`，保留最近 30 次；旧 captures 继续使用原保留规则。单次运行记录超过 50,000,000 字符或单事件超过 26,000,000 字符时，明确记录存储限制，不把缺失内容显示为完整记录。
- 工具返回标记为“已返回运行环境”；只有收到运行环境确认的内容标为已接收。模型服务内部指令及未开放的上下文压缩内容不能获取，会显示这一边界。记录中不包含凭据或运行连接密钥。
