# 开发与验证

从完整的 `paper-radar/` 源码目录运行：

```sh
node scripts/setup.mjs --verify
```

安装入口读取 `components.json`，核对组件版本，按两个锁文件安装插件与应用依赖，然后运行插件测试、应用类型检查、代码检查、自动测试和生产构建。`--check-only` 复用已有依赖执行同样的检查。

`plugins/dsh` 与 `web` 都通过 `@paper-radar/host-contract` 的包导出引用协议；路径移动后必须同时更新组件声明、两个锁文件和安装脚本。不要依赖开发机器上残留的符号链接。组件版本无需与宿主通信协议版本相同。

本应用由 PersonaStudio Git 统一管理，应用与插件可以在同一提交中调整。`work/`、依赖、构建结果和本机实验输出不进入 Git。

## 升级现有本机环境

1. 安装依赖并完成检查、构建。
2. 如需更新 DSH 插件，按插件 README 安装到实际宿主。
3. 当前任务结束后重启业务服务；插件更新后重启 DSH 并刷新其页面。

开发验证不会安装插件到运行中的宿主，也不会重启后台服务或调用真实模型。

代码和界面统一使用 DSH。为兼容已有安装，仍识别旧 `harness` 宿主标记、环境变量和设置路径；既有 socket 与通信协议版本不因源代码重命名而改变。旧操作表会在加载集成入口时迁移名称，保留请求幂等记录与会话关联。

历史独立模型任务仍可查看。原执行方式已经删除，恢复或重试时给出重新发起的提示；不会将历史任务自动转交当前宿主，也不会读取原凭据库。

## 需要覆盖的行为

- Codex 与 DSH 分别执行单篇分析和每日初筛，切换宿主不改变在途任务。
- 取消会阻止迟到提交；恢复保留已完成内容与既有证据。
- 自动日报遵守调用预算，未变化来源与失败候选不会隐式重跑。
- 旧账号、密钥、直连生成接口不存在；不支持的历史快照不会调用当前宿主。
- DSH 插件安装副本包含协议包，运行不依赖源码目录。

本轮只维护源码安装与本机运行，不设计发布打包流程。历史设计与验证记录集中在 `docs/archive/`，其中的旧路径和旧功能描述不代表当前能力。

## PersonaStudio 本机验证

从仓库根目录运行 `npm run setup:radar` 准备跨应用依赖，运行 `npm run check:radar` 完成检查。此入口强制执行 AI Persona 联调，并额外检查构建后的本机启动、备份、恢复与重启。测试使用临时数据，不调用真实模型。

正常启动不提供示例体验步骤。显式示例构建仅供开发使用。首次设置和数据管理位于 `web/server/runtime/` 与对应界面组件中；它们复用原有 Persona、订阅、任务与存储接口。
